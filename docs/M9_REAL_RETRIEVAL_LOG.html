2. 각각 무엇을 의미하나?

rc_

검색 규칙의 logical ID. IndexFlatIP, cosine/L2, query profile, Top-3, model/profile/dimension 계약을 식별합니다.

fi_

source embedding snapshot + index build profile의 logical FAISS artifact ID입니다.

mapping SHA

FAISS position → embedding_id → knowledge_item_id 연결표가 같은지 확인합니다.

FAISS binary SHA

이번에는 같은 머신/같은 환경에서 두 build가 byte-for-byte 동일했습니다. 좋은 신호지만 library/platform serialization 차이를 고려해 logical identity의 필수 조건으로 두지는 않습니다.

3. 왜 Rebuild Test를 했나?

same source + same retrieval contract ↓ rebuild ↓ same rc_ same fi_ same canonical mapping ↓ deterministic / reproducible PASS

이 검증은 정식 서비스에서 매번 전체 rebuild하겠다는 의미가 아닙니다. 파일럿에서 현재 구현이 시간값·랜덤 ordering·숨은 상태에 흔들리지 않는지 확인하는 Gate입니다.

4. Pilot vs Production

Pilot

full rebuild로 결정성, mapping, 무결성, exact baseline을 확인합니다.

Production

delta-first로 added/changed/removed Knowledge만 embedding/index에 반영하고, full rebuild는 maintenance/recovery/migration에 사용합니다.
