4. 운영 서비스의 핵심 루프

Sync 시작 ↓ upper 고정 Project Discovery ├─ 처음 보는 project_id → initial ingest ├─ visible 기존 Project → delta sync └─ unavailable 기존 Project → 이번 Sync에서 skip └─ 기존 Knowledge / Retrieval 유지 ↓ Issue Delta ├─ unchanged → reuse ├─ new → 새 Version └─ changed → 새 Version ↓ SOURCE_COMMITTED ↓ Knowledge / Evidence / Embedding / FAISS ↓ PUBLISHED ↓ Central Remote MCP
지식 보존: Project/Issue 삭제·비노출은 Knowledge 삭제 이벤트가 아닙니다. 기존 Published Knowledge는 계속 검색에 사용합니다.

5. 안전한 Publish

현재 Published = V1 새 Jira Source V2 = SOURCE_COMMITTED V2 Knowledge / Embedding / FAISS 준비 중 → 검색은 V1 유지 V2 전체 준비 완료 → Published Head V2 전환 → V1 History 보존

사용자에게 DB/Vector/Index가 서로 다른 세대인 Half-Publish를 노출하지 않습니다.

6. 현재 설계 단계

이 다섯 Entity를 중심으로 Watermark, Registry, Run 결과, downstream checkpoint를 저장하는 Schema를 검토 중입니다.

7. Remote MCP의 위치

Background Sync Pipeline Jira → RAW → Knowledge DB → Embedding / FAISS ↓ latest Published corpus Central Remote MCP ↓ team OpenCode clients

Remote MCP만 서버화하는 것으로는 부족합니다. Background Sync와 안전한 Publish가 함께 있어야 최신 지식 서비스가 됩니다.
