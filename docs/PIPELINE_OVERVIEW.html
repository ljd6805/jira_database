5. 운영 서비스의 핵심 루프

Sync 시작 ↓ Project Discovery ├─ new project → initial ingest ├─ existing project → delta sync └─ missing/no access→ 정책 판단 ↓ Issue Delta ├─ unchanged → reuse ├─ new → Version/Knowledge/Vector add └─ changed → new Version/Generation → active 교체 ↓ Embedding / FAISS Delta ↓ Central Remote MCP ↓ 팀원 OpenCode가 최신 Active Knowledge 조회

6. Production Update Direction

운영 기본 = delta-first unchanged → reuse added → cache/embed → add changed → remove/tombstone → cache/embed → add removed / no access → 정책 Freeze 후 active 처리 full rebuild = maintenance / recovery / migration

IndexIDMap2(IndexFlatIP), vector cache, HNSW/IVF는 실제 운영 측정 후 결정할 후보입니다.

7. Remote MCP의 위치

Background Sync Pipeline Jira → RAW → Knowledge DB → Embedding / FAISS ↓ latest Active corpus Central Remote MCP ↓ HTTPS team OpenCode clients

Remote MCP만 서버화하는 것으로는 부족합니다. 동기화 파이프라인이 함께 있어야 Jira 최신 상태가 검색 서비스에 반영됩니다.
