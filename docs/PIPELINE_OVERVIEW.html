2. 흔들리면 안 되는 원칙

RAW = Source of Truth

뒤 계층은 앞 계층에서 다시 만들 수 있는 파생물이어야 합니다.

History ≠ Active Retrieval

DB는 이력을 보존하지만 기본 검색 corpus는 active generation의 accepted attempt만 사용합니다.

Identity 분리

Knowledge ID, Embedding ID, FAISS position은 서로 다른 개념이며 섞지 않습니다.

RAW → ANALYSIS → KNOWLEDGE INPUT → KNOWLEDGE → DB → EMBEDDING → VECTOR

jira_id → iv_ → kc_ → kg_ → ka_(attempt_no) → ki_ → ke_

Embedding Contract  ec_
Embedding Artifact  emb_

FAISS position ≠ embedding_id ≠ knowledge_item_id

6. M9 · FAISS + Active Retrieval

현재 M9는 설계 단계입니다. 구현은 아직 시작하지 않았습니다. 최신 M9 문서에서 exact-search baseline과 향후 ANN 확장 경로를 다듬고 있습니다.

validated M8 embedding artifact ↓ M9 DESIGN - FAISS index type / metric / normalization - active-only policy - emb_ ↔ ki_ mapping - query embedding contract - Top-k baseline - rebuild / reproducibility - retrieval quality Gate ↓ M9 IMPLEMENTATION ↓ M10 Evidence Builder + MCP
책임 경계
M9는 검색 후보의 identity와 score까지 책임집니다. Evidence 원문 복원과 MCP 응답 구성은 M10의 책임입니다.
