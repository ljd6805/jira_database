2. 실제 Loop A 흐름

Jira /serverInfo → Jira server clock 기준 fixed upper 생성 → source_sync_run → Project Discovery 전체 성공 → project_id Registry 반영 → initial / delta / catch-up / unavailable 분기 Project별 → lower = committed_watermark - 5m (delta/catch-up) → upper = Source Run fixed upper → updated >= lower AND updated < upper → ORDER BY updated ASC, id ASC → candidate detail + comments RAW 저장 → Issue / Comment / Structure Parser 재사용 → 이슈 단위 ANALYSIS 저장 → Knowledge Input package 저장 → semantic_v2 hash → NEW / CHANGED / UNCHANGED → record_source_candidate() → Project 전체 안전 완료 → commit_source_project() → SOURCE_COMMITTED + Watermark + Source Ready + supersede

3. fixed upper는 Jira 시간 기준

Source Run 시작 시 /serverInfo를 읽고 Jira server time을 분 단위 경계로 고정합니다. JQL에는 Jira timezone으로 표현하고, State DB에는 UTC ISO 시각으로 저장합니다.

예시 Jira serverTime = 2026-08-31 20:40:42 +09:00 fixed upper = 2026-08-31 20:40 +09:00 State DB upper = 2026-08-31T11:40:00+00:00

Resume할 때는 새 현재시각을 만들지 않고 최초 Run의 upper_bound와 저장된 server timezone 정보를 그대로 재사용합니다.

4. Delta Query

Initial Ingest project = "ABC" AND updated < "2026-08-31 20:40" ORDER BY updated ASC, id ASC Delta / Catch-up project = "ABC" AND updated >= "2026-08-31 20:35" AND updated < "2026-08-31 20:50" ORDER BY updated ASC, id ASC

첫 Ingest에는 lower가 없습니다. 운영 기본은 전체 window이며 --max-issues-per-project는 테스트/파일럿 전용입니다.

6. Project Discovery 안전 규칙

Discovery 완전 성공

그때만 visible Project Registry를 갱신하고, 기존 Registry에만 남은 Project를 unavailable로 표시합니다.

Discovery 실패

기존 Project visibility를 전혀 바꾸지 않고 Source Run을 실패 처리합니다.

Project identity는 project_id이고 key/name은 변경 가능한 metadata입니다.

7. Project 단위 실패 격리

Project A candidate 1 ✓ candidate 2 ✓ Source Commit ✓ Watermark 전진 Project B candidate 1 ✓ candidate 2 ✗ Source Commit X Watermark 유지 cursor는 candidate 1까지 durable Project C 계속 진행

한 Project 실패 때문에 다른 Project의 정상 Source Commit을 되돌리지 않습니다.

8. Same-Run Resume

첫 시도 fixed upper = 20:40 ABC-1 완료 → cursor durable ABC-2 detail 실패 Watermark 이동 안 함 resume(source_run_id) → 같은 fixed upper = 20:40 → 같은 Discovery snapshot → ABC-1 cursor 이전이므로 skip → ABC-2부터 재시도 → 성공 후 Project Source Commit → Watermark = 20:40

같은 Run 재개가 불가능한 경우에는 이후 새 Run이 기존 committed Watermark - 5분 overlap부터 다시 잡도록 계약이 유지됩니다.
