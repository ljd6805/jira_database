McpRuntimeSettingsError

M10 Real-run에서 SQLite와 FAISS artifact를 열기 전에 필요한 로컬 경로 환경변수가 없거나, 지정한 경로가 실제로 존재하지 않을 때 발생하는 설정 오류입니다.

RUNTIME SETTINGS ISSUE · FAISS SEARCH 전 단계
먼저 이해하기

이 에러가 났을 때 FAISS 검색은 아직 시작되지 않았습니다

M10_REAL_RUN_QUERY ↓ 런타임 설정 로드 ├─ JIRA_KNOWLEDGE_DB_PATH 확인 └─ JIRA_RETRIEVAL_ARTIFACT_DIR 확인 ↓ 여기까지 성공해야 ↓ BGE-M3 → FAISS → ki_ → ke_ → source

McpRuntimeSettingsError는 위의 경로 준비 단계에서 멈춘 것입니다. FAISS가 Jira 원문을 직접 검색하는 구조도 아닙니다. FAISS는 Knowledge vector를 검색하고, SQLite가 해당 Knowledge의 실제 Evidence source를 복원합니다.

필수 경로 2개

환경변수가리키는 것
JIRA_KNOWLEDGE_DB_PATHM7에서 만든 실제 SQLite DB 파일
JIRA_RETRIEVAL_ARTIFACT_DIRM9의 index.faiss, index.mapping.jsonl, index.manifest.json가 있는 디렉터리

Windows PowerShell 확인

Test-Path ".\data\knowledge_db\validation\20260804T043628Z.sqlite3" Test-Path ".\data\retrieval\runs\20260804T043628Z"

두 명령 모두 True여야 합니다. 실제 artifact 위치가 다르면 자신의 로컬 경로에 맞게 바꿉니다.

$env:JIRA_KNOWLEDGE_DB_PATH = (Resolve-Path ".\data\knowledge_db\validation\20260804T043628Z.sqlite3").Path $env:JIRA_RETRIEVAL_ARTIFACT_DIR = (Resolve-Path ".\data\retrieval\runs\20260804T043628Z").Path Write-Host "DB:" (Test-Path $env:JIRA_KNOWLEDGE_DB_PATH) Write-Host "FAISS:" (Test-Path $env:JIRA_RETRIEVAL_ARTIFACT_DIR)

정상이면 DB: True, FAISS: True가 출력됩니다.

나중에 Linux로 포팅하면

export JIRA_KNOWLEDGE_DB_PATH="/path/to/knowledge.sqlite3" export JIRA_RETRIEVAL_ARTIFACT_DIR="/path/to/retrieval/run" test -f "$JIRA_KNOWLEDGE_DB_PATH" && echo "DB OK" test -d "$JIRA_RETRIEVAL_ARTIFACT_DIR" && echo "FAISS DIR OK"

이번 실전에서 배운 점

✓ Query가 설정돼도 DB/FAISS 경로가 없으면 검색은 시작되지 않는다.
✓ FAISS는 원문 저장소가 아니라 Knowledge vector 검색기다.
✓ 원문 Evidence는 FAISS 결과의 ki_를 따라 SQLite의 ke_에서 복원한다.
✓ 로컬 artifact 경로는 공개 문서에 절대경로로 기록하지 않는다.
