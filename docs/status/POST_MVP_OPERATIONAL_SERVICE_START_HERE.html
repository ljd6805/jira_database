4. 다시 뒤집지 않을 원칙

Source Loop ≠ Processing Loop

서로 독립 Scheduler/Run/실패 경계를 가집니다.

SOURCE_COMMITTED ≠ PUBLISHED

Source Commit은 Loop A, Publish는 Loop B.

Jira Lifecycle ≠ Knowledge Lifecycle

Jira 비노출/삭제가 Knowledge 삭제를 뜻하지 않습니다.

Last-known-good Retrieval

새 Publish 전까지 기존 Published Knowledge를 계속 제공합니다.

Delta-first

5분 overlap + fixed upper + semantic_v2로 실제 변경만 downstream.

Fail Forward

완료 결과는 유지하고 실패한 Loop/Stage만 재시도합니다.

7. 다음에 반드시 결정할 것

Intermediate Version supersede

V2→V3→V4가 Loop B 처리 전에 쌓인 경우 모든 semantic Version을 OpenCode로 처리할지, 아직 시작하지 않은 구버전 Work를 supersede하고 최신 pending을 처리할지 결정해야 합니다.

아직 결정하지 말 것

Multi-worker lease, 외부 MQ, 정확한 시간대별 cadence/concurrency는 실제 Single Worker 데이터와 backlog를 측정한 뒤 결정합니다.
