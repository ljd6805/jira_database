검증

Artifact first

canonical Knowledge/Review가 durable한 뒤에만 knowledge_status=completed를 기록합니다.

6. A → B → A edge case

A Knowledge running → B Source Commit → A superseded → 나중에 Jira가 다시 semantic A → 같은 sw_A 재활성화 → 과거 knowledge_status=running이 남아도 retryable 처리 → 최신 A Knowledge checkpoint 완료

Published A가 돌아오는 경우는 기존 artifact 재사용 정책이 유지됩니다. 이번 보강은 미완료 stale-running 상태가 재활성화되는 경우입니다.

9. 현재 다음 구현 · Operational Data Plane

per-Work Knowledge DB Materializer

기존 M7 loader는 full-run manifest를 전제로 합니다. 새 운영 흐름은 per-Issue incremental artifact이므로 기존 loader를 억지로 호출하지 않고, Work Item 하나를 Knowledge DB의 Issue Version / Generation / Attempt / Knowledge Item / Evidence / Review로 materialize하는 전용 경로를 만듭니다.

Knowledge checkpoint → per-Work Knowledge DB materialization → active/accepted generation 검증 → incremental BGE-M3 → FAISS staging + mapping → latestness re-check → Atomic active view switch → State published second
