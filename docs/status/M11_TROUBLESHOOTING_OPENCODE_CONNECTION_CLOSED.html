M11 TROUBLESHOOTING · 2026-08-27

OpenCode MCP error -32000:
Connection closed

OpenCode가 local stdio MCP 프로세스를 시작했지만 handshake를 완료하기 전에 연결이 닫힌 경우의 진단 기록입니다.

M11-02 TROUBLESHOOTING

실제 관찰된 메시지

jira-knowledge failed MCP error -32000: Connection closed python -m jira_collector.mcp_server.server

직접 실행에서 발견한 RuntimeWarning

<frozen runpy>:128: RuntimeWarning: 'jira_collector.mcp_server.server' found in sys.modules after import of package 'jira_collector.mcp_server', but prior to execution of 'jira_collector.mcp_server.server'; this may result in unpredictable behaviour

이 메시지는 traceback이 있는 치명적 예외가 아니라 Python의 RuntimeWarning입니다. 따라서 이것만으로 OpenCode의 Connection closed 원인을 확정하지 않습니다. 다만 stdio MCP entrypoint의 import 구조가 잘못됐다는 신호이므로 먼저 제거했습니다.

원인

python -m jira_collector.mcp_server.server ↓ Python이 먼저 package __init__.py import ↓ __init__.py가 .server를 eager import ↓ server 모듈이 sys.modules에 이미 존재 ↓ runpy가 같은 server 모듈을 다시 -m으로 실행 ↓ RuntimeWarning

수정

jira_collector.mcp_server.__init__에서 server.py를 즉시 import하지 않고 create_mcp_server() 호출 시에만 지연 import하도록 변경했습니다. 기존 public import API는 유지합니다.

재검증 순서 · Windows PowerShell

git pull python -m jira_collector.mcp_server.server

정상이라면 RuntimeWarning 없이 프로세스가 종료되지 않고 stdio 요청을 기다립니다. 직접 실행에서는 Ctrl+C로 종료합니다.

opencode mcp list

그 다음 OpenCode 연결을 다시 확인합니다. 여전히 Connection closed라면 다음 원인은 Python executable, cwd, MCP handshake/protocol 순서로 분리해서 조사합니다.

중요한 판단

아직 M11-02 PASS가 아닙니다. RuntimeWarning 수정은 한 원인을 제거한 것입니다. 실제 opencode mcp list에서 jira-knowledge가 connected 상태가 되어야 OpenCode 등록 Gate를 PASS로 판정합니다.
