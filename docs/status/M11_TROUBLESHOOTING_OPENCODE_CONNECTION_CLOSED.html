M11 TROUBLESHOOTING · 2026-08-27

OpenCode MCP error -32000:
Connection closed

OpenCode가 local stdio MCP 프로세스를 시작하지만 handshake를 완료하지 못하는 경우의 단계별 진단 기록입니다.

M11-02 TROUBLESHOOTING · STDIO BOUNDARY ISOLATION

현재까지 실제 관찰

1) OpenCode jira-knowledge failed MCP error -32000: Connection closed python -m jira_collector.mcp_server.server 2) PowerShell 직접 실행 python -m jira_collector.mcp_server.server → RuntimeWarning 수정 후 아무 출력 없이 계속 대기 → stdio server process 자체는 살아 있음 3) OpenCode 재시도 → 여전히 Connection closed

따라서 현재는 .env, SQLite, FAISS가 즉시 프로세스를 죽이는 단계는 지나갔습니다. 다만 터미널에서 대기한다는 사실만으로 MCP initialize handshake가 정상이라고 판정할 수는 없습니다.

처음 발견했던 RuntimeWarning

<frozen runpy>:128: RuntimeWarning: 'jira_collector.mcp_server.server' found in sys.modules after import of package 'jira_collector.mcp_server', but prior to execution of 'jira_collector.mcp_server.server'

이 경고는 mcp_server.__init__의 eager import 때문에 생겼고 lazy import로 수정했습니다. 이후 직접 실행에서 경고가 사라지고 서버가 정상 대기하는 것을 확인했습니다.

왜 아직 원인이 확정되지 않았나?

터미널 직접 실행 = 프로세스가 시작되고 stdin을 기다릴 수 있는지 확인 실제 MCP host 연결 = subprocess spawn → MCP initialize JSON-RPC → initialize response → notifications/initialized → tools/list OpenCode 실패는 이 handshake 경계에서 발생할 수 있음

다음 진단: OpenCode를 제외한 실제 stdio handshake

공식 MCP Python Client가 우리 서버를 실제 subprocess로 띄워 initialize → tools/list를 수행하는 검증기를 추가했습니다.

git pull python tools/jira_knowledge/validate_m11_stdio_transport.py

정상이면 다음처럼 안전한 정보만 출력합니다.

python_executable: ... tool_count: 2 tools: get_jira_issue, search_jira_knowledge M11_STDIO_HANDSHAKE = PASS

실패하면 실제 Jira 내용이나 secret 대신 실패 stage와 exception type만 출력합니다.

failure_stage: spawn_or_initialize 또는 list_tools error_type: ... M11_STDIO_HANDSHAKE = FAIL

결과 해석

stdio validatorOpenCode판단
PASSConnection closed우리 MCP stdio는 정상. OpenCode의 Python executable / cwd / host compatibility를 조사
FAIL · spawn_or_initializeConnection closed우리 subprocess stdio initialize 경계 문제. OpenCode보다 먼저 MCP transport를 수정
PASSconnectedM11-02 등록 + M11-03 Tool discovery PASS 후보

PASS인데 OpenCode만 실패하면 다음 순서

1. python -c "import sys; print(sys.executable)" 2. opencode.jsonc command를 해당 python 절대경로로 임시 고정 3. cwd가 실제 jira_database workspace인지 확인 4. opencode mcp list 재실행 5. 필요 시 OpenCode MCP 로그/프로토콜 호환성 조사

처음부터 protocol 문제라고 단정하지 않고 executable과 cwd를 먼저 제거합니다.

중요한 판단

아직 M11-02 PASS가 아닙니다. 실제 opencode mcp list에서 jira-knowledge가 connected가 되어야 등록 Gate를 PASS로 판정합니다.
