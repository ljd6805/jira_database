사용자가 문서의 v1/v2/v3 표기를 이해하기 어렵다고 피드백하여, 전체 사람용 문서의 버전 언어와 현재/과거 상태 표시를 재정렬했습니다.

1. 문제

숫자만 보임

v1/v2/v3가 무엇의 버전인지 본문을 읽기 전에는 알기 어려웠습니다.

독립 번호가 섞임

Operational State, Knowledge DB, Document Shell, ID 알고리즘, hash profile의 번호가 같은 체계처럼 보였습니다.

과거 문서 혼입

개정 2 시점의 Easy Guide와 Decision 문서가 현재 문서처럼 읽히는 부분이 있었습니다.

3. 전체 문서에 적용한 방식

공통 Document Shell

버전 표현이 있는 모든 HTML에서 펼쳐볼 수 있는 “버전 숫자 읽는 법” 도움말을 자동 제공합니다.

Historical 자동 표시

Baseline 문서는 공통 Shell에서 과거 보관본/현재 구현 기준 아님을 표시합니다.

핵심 문서 직접 수정

Hub, Sync Contract, State Schema, DDL, Two-Loop, Easy/Detailed Guide, State S1~S6, D7/D8, Baseline 문서를 현재 의미로 정렬했습니다.

관계도 시각화

State DB 현재 개정 3과 Knowledge DB 구현 개정 1을 독립된 번호 체계로 표시하고 cross-DB logical reference는 점선으로 구분합니다.

4. 내용 불일치도 함께 수정

단순 이름 치환만 하지 않았습니다. 개정 2 시점 문서에 남아 있던 “Intermediate Version supersede 미결정”을 제거하고, 현재 확정된 Latest-Only / supersede / stale in-flight guard 규칙을 Easy Guide, Detailed Guide, 2-Loop Architecture, State S3/S4, D7 등에 반영했습니다.
