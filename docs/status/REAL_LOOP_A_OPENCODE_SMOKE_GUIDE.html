REAL SMOKE GUIDE · 2026-08-31

Project 1개 → Issue 1개 → Source Ready → Real OpenCode

Production/Pilot data를 건드리지 않고 data_smoke/에서 실제 Jira Loop A와 실제 사내 OpenCode Knowledge Automation을 연속 검증합니다.

0. 이번 Smoke의 성공 정의

G1 · REAL LOOP A Project 1개 발견 → Issue 최대 1개 수집 → RAW / ANALYSIS / Knowledge Input 생성 → SOURCE_COMMITTED → Source Ready Work 1건 G2 · REAL INTERNAL OPENCODE Source-ready latest Work 1건 → run_knowledge_worker.py → opencode run --agent jira-knowledge-orchestrator → Knowledge / Review artifact 생성 → Validator / Reviewer PASS → knowledge_status = completed 별도 확인 실제 jira-knowledge-extraction Skill load trace → OpenCode 실행 trace가 보일 때 확인 → runner 자체는 현재 성공 stdout/stderr를 보존하지 않으므로 trace가 없으면 PENDING 유지

1. 최신 코드 받기

git pull

--project-key 옵션이 포함된 최신 main을 사용합니다.

2. Project Key 지정

export PROJECT_KEY="YOUR_PROJECT_KEY"

예: Jira 이슈가 ABC-123이면 Project Key는 보통 ABC입니다.

3. Jira 인증정보 존재 여부만 확인

python - <<'PY'
import os
from dotenv import load_dotenv
load_dotenv()
for key in ("JIRA_BASE_URL", "JIRA_USERNAME", "JIRA_PASSWORD"):
    print(f"{key} = {'SET' if os.getenv(key) else 'MISSING'}")
PY

값 자체는 화면에 출력하지 않습니다. 세 항목 모두 SET이어야 합니다.

4. Smoke 환경 초기화

rm -rf data_smoke
중요

Smoke는 Resume하지 않습니다. 실패하면 원인을 고친 뒤 data_smoke/를 지우고 처음부터 다시 실행합니다.

5. 옵션 존재 확인

python tools/run_source_sync.py --help | grep -E "project-key|max-issues-per-project"

--project-key와 --max-issues-per-project가 보여야 합니다.

6. Real Loop A Smoke 실행

python tools/run_source_sync.py \
  --local-config config/settings.smoke.yaml \
  --project-key "$PROJECT_KEY" \
  --max-issues-per-project 1

--project-key는 data_smoke root에서만 허용됩니다. Production data/에서 실행하려 하면 코드가 거부합니다.

7. Loop A 성공 출력 확인

SOURCE_SYNC = COMPLETED
source_run_id = sr_...
smoke_project_key = ...
visible_project_count = 1
source_committed_project_count = 1
failed_project_count = 0
state_db = data_smoke/state/collector.db

Project에 candidate Issue가 하나도 없으면 Source Commit은 성공해도 Work Item이 0개일 수 있습니다. 그 경우 다른 Project를 선택해 Smoke를 다시 시작합니다.

8. Source Ready Work 확인

python - <<'PY'
import sqlite3
from pathlib import Path

db = Path("data_smoke/state/collector.db")
con = sqlite3.connect(db)
con.row_factory = sqlite3.Row
rows = con.execute("""
SELECT work_item_id, observed_issue_key, work_status,
       last_observed_source_run_id, last_source_committed_run_id,
       knowledge_status, embedding_status, publish_status
FROM sync_issue_change
ORDER BY created_at, work_item_id
""").fetchall()

print(f"work_count = {len(rows)}")
for row in rows:
    ready = (
        row["last_source_committed_run_id"] is not None
        and row["last_source_committed_run_id"] == row["last_observed_source_run_id"]
        and row["work_status"] in ("pending", "failed")
    )
    print(dict(row))
    print(f"SOURCE_READY = {ready}")

if not rows:
    raise SystemExit("NO_WORK_ITEM")
if not any(
    row["last_source_committed_run_id"] is not None
    and row["last_source_committed_run_id"] == row["last_observed_source_run_id"]
    and row["work_status"] in ("pending", "failed")
    for row in rows
):
    raise SystemExit("NO_SOURCE_READY_WORK")
PY
G1 PASS 조건

work_count >= 1이고 최소 한 행에서 SOURCE_READY = True가 출력됩니다.

9. 생성 파일 눈으로 확인

find data_smoke/raw data_smoke/analysis data_smoke/knowledge_input \
  -type f | sort | head -80

RAW, per-Issue ANALYSIS, Knowledge Input JSON이 실제로 만들어졌는지 확인합니다.

10. OpenCode 사전 확인

opencode --version

test -f .opencode/agents/jira-knowledge-orchestrator.md && echo "orchestrator = OK"
test -f .opencode/agents/jira-knowledge-worker.md && echo "worker = OK"
test -f .opencode/agents/jira-knowledge-reviewer.md && echo "reviewer = OK"
test -f .opencode/skills/jira-knowledge-extraction/SKILL.md && echo "skill = OK"

네 로컬 Agent/Skill 파일이 존재해야 합니다.

11. Real Internal OpenCode Knowledge Smoke

python tools/run_knowledge_worker.py \
  --local-config config/settings.smoke.yaml \
  --model-profile internal-opencode-knowledge-v1 \
  --limit 1

이 명령부터는 실제 사내 OpenCode 호출이 발생할 수 있으므로 평소보다 오래 걸릴 수 있습니다.

12. Knowledge Worker 결과 확인

KNOWLEDGE_WORKER = CHECKPOINTED
processing_run_id = pr_...
selected_count = 1
knowledge_completed_count = 1
failed_count = 0

failed_count = 0과 knowledge_completed_count = 1이 핵심입니다.

13. State DB에서 Knowledge checkpoint 확인

python - <<'PY'
import sqlite3

con = sqlite3.connect("data_smoke/state/collector.db")
con.row_factory = sqlite3.Row
rows = con.execute("""
SELECT work_item_id, observed_issue_key, work_status,
       knowledge_status, issue_version_id, knowledge_generation_id,
       embedding_status, publish_status
FROM sync_issue_change
ORDER BY updated_at DESC
""").fetchall()
for row in rows:
    print(dict(row))
PY

성공한 Work는 knowledge_status = completed이고 issue_version_id, knowledge_generation_id가 채워져 있어야 합니다. Embedding이 아직 전이면 work_status는 다음 Stage를 위해 다시 pending일 수 있습니다.

14. Knowledge / Review 파일 확인

find data_smoke/knowledge -type f | sort

최종 Knowledge JSON과 Attempt별 Review JSON이 존재하는지 확인합니다.

15. Skill-load trace는 별도 항목

현재 OpenCodeKnowledgeProcessor는 성공한 opencode run의 stdout/stderr를 캡처하지만 파일로 보존하지 않습니다. 따라서 위 Smoke가 성공하면 자동 Knowledge 경로가 실제 사내 OpenCode에서 성공했다는 것은 확인할 수 있지만, 실제 Skill tool load trace를 증명하려면 OpenCode 측 trace/log에서 jira-knowledge-extraction 호출 흔적을 추가 확인해야 합니다.

trace가 보이지 않으면 이 항목만 PENDING으로 남깁니다. Worker 정의상 Skill 사용은 REQUIRED입니다.

16. 실패했을 때

Project not found → PROJECT_KEY 확인 → 해당 계정이 Project를 조회할 수 있는지 확인 SOURCE_SYNC = FAIL → error 원인 확인 → rm -rf data_smoke → Loop A부터 다시 work_count = 0 → 비어 있지 않은 다른 Project 선택 → rm -rf data_smoke → Loop A부터 다시 KNOWLEDGE_WORKER = FAIL → data_smoke는 지우지 말고 오류를 먼저 기록 → OpenCode/Agent/Review 실패 원인 확인 → 필요 시 Smoke를 처음부터 재실행
