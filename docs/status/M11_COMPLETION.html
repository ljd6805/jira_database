3. 실제 사용자 환경에서 확인된 행동

자동 Tool 선택

자연어 업무 질문에서 MCP나 Tool 이름을 지시하지 않아도 OpenCode가 Jira MCP를 호출했습니다.

근거 Round-trip

후속 근거 요청에서 Jira 원본 description 또는 comment를 가져와 제시했습니다.

일반 업무 질문 → OpenCode 판단 → search_jira_knowledge 자동 호출 → Top-3 Knowledge + Evidence → Agent 답변 → 근거 요청 → 원본 description / comment Evidence 확인

공개 문서 Privacy 경계: 실제 업무 질문, Issue key, Jira 원문은 기록하지 않습니다. 대신 PASS 여부, Tool 이름, Evidence type처럼 재현에 필요한 안전한 정보만 남깁니다.

5. 중요한 해석

M11은 서비스 전체 완료가 아니라 Functional MVP 완료입니다.

여기까지는 수집된 Pilot 데이터를 가지고 검색·근거·MCP·Agent 소비 흐름이 실제로 되는지를 증명했습니다. Jira가 계속 변할 때 자동으로 수집·재처리·인덱스 갱신되는 운영 기능은 이후 단계의 범위입니다.

6. 최종 서비스는 지속 동기화 파이프라인 + Remote MCP입니다

Jira ↓ Project Discovery / Delta Sync RAW / Issue Version ↓ 변경분만 Knowledge / Evidence ↓ 변경분만 Embedding / FAISS ↓ 최신 Active corpus Central Remote MCP / HTTPS ↓ 팀원 OpenCode

Remote MCP는 중요한 서비스 경계지만 전체 서비스의 한 구성요소입니다. Jira 업데이트가 Knowledge/FAISS까지 지속 반영되지 않으면 중앙 MCP가 오래된 지식을 제공하게 됩니다.
