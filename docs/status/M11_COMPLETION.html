M11의 목적은 이미 완성된 jira-knowledge MCP를 외부 소비자인 OpenCode Agent가 실제로 발견하고, 필요할 때 호출하고, 답변 근거까지 추적할 수 있는지 확인하는 것이었습니다.

3. 실제 사용자 환경에서 확인된 행동

자동 Tool 선택

과거에 유사한 문제가 있었는지 묻는 자연어 업무 질문에서 MCP나 Tool 이름을 지시하지 않아도 OpenCode가 Jira MCP를 호출했습니다. 따라서 Tool discovery만 된 것이 아니라 Agent의 실제 tool-selection 경로가 동작합니다.

근거 Round-trip

첫 답변 뒤 근거를 요구하는 후속 질문에서 OpenCode가 Jira 원본의 description 또는 comment를 가져와 제시했습니다. Knowledge 답변에서 실제 Evidence source까지 다시 내려가는 경로가 사용자 관점에서도 확인됐습니다.

일반 업무 질문 ↓ OpenCode 판단 ↓ search_jira_knowledge 자동 호출 ↓ Top-3 Knowledge + Evidence ↓ Agent 답변 ↓ "그 판단의 근거는?"와 같은 후속 질문 ↓ 원본 description / comment Evidence 확인

공개 문서 Privacy 경계: 실제 업무 질문, Issue key, Jira 원문은 기록하지 않습니다. 대신 PASS 여부, Tool 이름, Evidence type처럼 재현에 필요한 안전한 정보만 남깁니다.

4. 이 결과가 의미하는 것

검색 경로

BGE-M3 → FAISS → Knowledge 검색이 Agent 사용 흐름 안에서도 작동합니다.

근거 경로

ki_ → ke_ → Jira source의 Evidence round-trip이 OpenCode 사용자 경험으로 이어집니다.

Agent 분리

생성형 Agent를 이 저장소에 포함시키지 않고도 OpenCode 같은 외부 Agent가 MCP를 소비할 수 있음을 확인했습니다.

5. 중요한 해석: M11-06의 범위

모든 첫 답변에 원문을 자동으로 길게 표시해야 한다는 뜻은 아닙니다.

M11에서 확인한 핵심은 Agent가 Knowledge/Evidence를 이용할 수 있고, 사용자가 근거를 요구하면 실제 source까지 추적할 수 있다는 점입니다. 첫 답변의 기본 인용 형식이나 자동 출처 표시는 향후 제품 UX 정책으로 별도 결정할 수 있습니다.

6. Local stdio는 최종 서비스 형태가 아닙니다

M11 Pilot OpenCode ── local stdio ──→ MCP child process 최종 팀 서비스 목표 팀원 A OpenCode ─┐ 팀원 B OpenCode ─┼── Remote MCP / HTTPS ─→ 중앙 jira-knowledge MCP 팀원 C OpenCode ─┘ ├─ SQLite ├─ FAISS ├─ .env └─ BGE-M3 API

M11은 기능/호환성 Pilot을 닫는 단계입니다. 팀원 모두에게 제공하는 실제 서비스에서는 중앙 서버가 데이터와 secret을 소유하고, 팀원 OpenCode는 Remote MCP endpoint만 소비하는 구조를 목표로 합니다.

7. M11에서 해결한 주요 문제

runpy RuntimeWarning

mcp_server.__init__의 eager import를 lazy import로 바꿔 python -m jira_collector.mcp_server.server entrypoint 경고를 제거했습니다.

Connection closed

다른 OpenCode workspace에서 cwd="."를 사용하면 MCP가 jira_database의 .env/상대 artifact 기준을 잃는다는 점을 확인했습니다. 같은 프로젝트 루트의 local Pilot에서 정상 연결을 확인했습니다.

stdio 실제 검증

공식 MCP client가 subprocess를 실행해 initialize → tools/list를 수행하는 별도 validator에서 M11_STDIO_HANDSHAKE = PASS를 확인했습니다.

서비스 설정

실제 서비스 기본값은 .env, OS env는 override, 테스트 명시 env는 .env 미사용으로 정책을 고정했습니다.
