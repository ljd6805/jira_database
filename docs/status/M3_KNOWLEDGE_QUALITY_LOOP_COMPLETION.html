1. 실행 구조

Orchestrator ↓ 경로·상태만 관리 Fresh Worker · Issue 1건 ↓ Python Validator ↓ Fresh Defect Reviewer ↓ PASS / REGENERATE ↓ 필요 시 새 Worker Context에서 전체 재생성
핵심은 Reviewer 추가가 아닙니다. Primary Context에는 workflow state만 남기고, Issue semantics는 child context 하나에 격리합니다.

2. 역할 분리

Orchestrator

입출력 경로, 호출 순서, 상태, 다음 Issue 이동 여부만 관리. Jira 본문을 분석하지 않습니다.

Worker

Knowledge Input 한 건과 Skill v0.9만 읽어 Knowledge 전체를 생성합니다.

Reviewer

Fresh context에서 결함 중심으로 Fact/Causal/Evidence/Classification/Missing/Duplication audit를 수행합니다.

JSON Schema, required field, evidence ref pattern 같은 구조 오류는 Python Validator가 맡습니다. 의미 오류와 구조 오류를 같은 LLM 판단에 섞지 않습니다.

3. 순차 처리와 재생성 계약
