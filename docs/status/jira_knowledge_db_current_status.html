3. Incremental Embedding 안전 규칙

Candidate를 직접 임베딩

운영 Materializer는 Publish 전이므로 Generation을 active로 만들지 않습니다. Embedding은 해당 candidate의 accepted attempt를 직접 읽습니다.

Slow API stale guard

BGE-M3 응답 뒤 최신 Source인지 다시 확인합니다. 새 Version이 들어왔으면 구버전은 completed로 만들지 않습니다.

Artifact first

corpus/embedding 파일을 atomic 저장한 뒤에만 embedding_status=completed를 기록합니다.

Stage-local Processing Run

Embedding 완료 후 Work는 다시 pending으로 풀려 다음 Publish Processing Run이 이어받습니다.

4. Source History / Latest-Only

Source History A → B → C → D 모두 보존 AI / Data Plane B pending/running → newer Source로 superseded 가능 C pending → superseded D latest + Source-ready → Knowledge → Knowledge DB candidate → Embedding staging → Publish 준비
