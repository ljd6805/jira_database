데이터 계층

사실 데이터와 Agent 해석을 분리합니다. 이 계층 경계는 향후 DB/RAG/MCP 품질 검증의 기준입니다.

[RAW]

Source of Truth

Jira API 원본. Parser가 수정하지 않는 재처리 기준입니다.

[ANALYSIS]

정규화된 사실

Issue, Comment, Attachment, Relationship, Custom Field를 deterministic JSONL로 저장합니다.

[KNOWLEDGE INPUT]

Issue 단위 사실 패키지

여러 ANALYSIS JSONL을 issue_key로 JOIN하여 Agent가 한 파일로 읽게 만듭니다.

[KNOWLEDGE]

다음: 구조화 지식

OpenCode Agent가 원인·계획·결정·결과·결론 등을 evidence와 함께 추출합니다.

[DB]

향후 관계형 저장

Issue/Comment/Relationship/Custom Field/Knowledge/Evidence를 row 기반으로 연결합니다.

[VECTOR]

향후 의미 검색

BGE-M3 + FAISS. Vector는 후보 검색기이며 원문 저장소가 아닙니다.

[RAW 데이터 경로] data/raw/runs/<run_id>/projects/<PROJECT>/issues/<ISSUE>/issue.json 용도: Jira API 원본 Issue 구조 보존
[ANALYSIS 데이터 경로] data/analysis/<run_id>/ 용도: deterministic Parser / Exporter 정규화 산출물
[KNOWLEDGE INPUT 데이터 경로] data/knowledge_input/runs/<run_id>/issues/<ISSUE_KEY>.json 용도: OpenCode Agent가 읽는 Issue 단위 최종 사실 패키지
[KNOWLEDGE 데이터 경로 · 예정] data/knowledge/<run_id>/... 용도: Agent가 생성한 구조화 업무 지식과 evidence 보존

Stage 4 완료

IssueStructureParser / Exporter

각 issue.json을 한 번 읽어 다음 구조를 함께 추출합니다.

  • Attachment metadata
  • Issue Link
  • Parent/Subtask hierarchy
  • Custom Field Catalog
  • Custom Field Values
Stage 5 완료

IssueKnowledgeInputBuilder

ANALYSIS만 읽고 RAW를 다시 열지 않습니다.

  • Issue + Comments + Attachments
  • Canonical Relationships
  • 실제 값이 있는 Custom Fields
  • source_hash 생성
  • manifest 마지막 원자 저장
중요한 품질 경계KNOWLEDGE INPUT이 틀리면 Collector/Parser/Join 문제이고, KNOWLEDGE INPUT이 정확한데 추출된 지식이 틀리면 Agent/Prompt/Schema 문제입니다.
source_hash의 의미Issue + Comments + Attachments + Relationships + Custom Fields의 의미 데이터로 SHA-256을 만들고, generated_at/source_path 같은 환경 의존 정보는 제외합니다. 향후 같은 hash면 Agent 재분석을 생략할 수 있습니다.

새 프로젝트·새 이슈·새 Schema 대응 원칙

이 부분은 추가로 확정한 운영 강화 요구사항입니다. 현재 Structure Export는 완료됐지만, run 간 schema 변화 감지 자체는 아직 별도 기능으로 구현되지 않았습니다.

1. Snapshot

Catalog는 run별 정의 스냅샷

매 run마다 names + schema를 다시 관찰합니다. Global master를 무조건 덮어쓰지 않습니다.

2. Non-fatal

모르는 구조가 와도 전체 Export는 계속

Known handler가 없으면 generic safe fallback을 사용하고 warning/observation을 남깁니다.

3. History

변경은 이력으로 보존

동일 field_id의 name/schema 변경을 오류로 숨기지 않고 시간에 따른 정의 변화로 기록합니다.

[ANALYSIS 데이터 경로] data/analysis/<run_id>/custom_field_catalog.jsonl 용도: 해당 run에서 실제 관찰한 Custom Field 정의 Snapshot
[ANALYSIS 데이터 경로 · 계획] data/analysis/<run_id>/schema_observations.json 용도: 이전 run과 비교한 NEW / CHANGED / MISSING / unsupported / new_unmapped_field 기록

향후 로드맵

현재 완료 상태를 반영해 다음 단계 중심으로 재정렬했습니다.

1. Jira RAW Collection ✅

접근 가능한 프로젝트 발견, 최근 이슈 수집, 댓글 페이지 수집, SHA-256 검증, resume까지 완료.

2. Issue / Comment ANALYSIS ✅

HTML 정제, author 정규화, JSONL export, summary/warning 완료.

3. Structure ANALYSIS ✅

Attachment 79, Relationship 6, Custom Field Catalog 220 / Values 447까지 완료.

4. Knowledge Input Builder ✅

30개 Issue 패키지, source_hash, manifest, package warning 체계 완료.

5. Schema Observation / 운영 Hardening ⬜

새 project/run에서 신규·변경·누락·미지원 구조를 run 간 비교하고 unknown schema를 non-fatal로 흡수합니다.

6. OpenCode Agent Knowledge Extraction ⬜

대표 이슈 5건으로 problem/goal, observation, hypothesis, confirmed cause, action, plan, decision, result, conclusion, evidence_refs schema를 검증합니다.

7. Human Validation ⬜

과잉 추론, 근거 누락, 상태 구분 오류를 검토하고 prompt/schema를 안정화합니다.

8. Knowledge Persistence ⬜

model/prompt/version/source_hash/evidence_refs를 포함해 재현 가능한 KNOWLEDGE 산출물을 저장합니다.

9. Profiling / Excel / Data Quality ⬜

Custom Field 사용도, 관계 밀도, 결측, 지식 coverage를 정량 검토합니다.

10. DB Schema / SQLite ⬜

Custom Field는 컬럼 추가가 아닌 Catalog/Values row 모델로 저장합니다.

11. Chunk / BGE-M3 / FAISS ⬜

Raw + Knowledge를 검색 대상으로 구성하고 사내 BGE-M3 dense 1024-d embedding을 사용합니다.

12. Retrieval Validation / Evidence Builder ⬜

벡터 후보 → DB → 원문/지식 복원이 LLM 없이 검증 가능해야 합니다.

13. Jira Knowledge MCP ⬜

MCP는 생성형 LLM 없이 deterministic search/get/evidence 도구를 제공하고 최종 해석은 상위 Agent가 수행합니다.

다음 완료 기준

현재 다음 작업에서 확인할 최소 기준입니다.

□ Run 간 Schema 비교field_id 신규/변경/누락을 기존 run snapshot과 비교할 수 있음
□ Unknown schema non-fatal지원하지 않는 타입이 와도 전체 Structure Export가 중단되지 않음
□ Unmapped Jira field 관찰새 일반 필드가 조용히 누락되지 않고 observation으로 남음
□ PII-safe fallbackgeneric object를 전체 dump하지 않고 safe display/shape만 유지
□ Knowledge Extraction 5건 파일럿모든 지식 항목이 evidence와 연결되고 추측/확정 사실이 분리됨
□ source_hash 증분 전략변경 없는 패키지는 Agent 재추출 생략 가능

확정 설계 원칙

향후 기능 추가에도 유지해야 할 기준입니다.

1
RAW JSON은 Source of Truth

ANALYSIS/KNOWLEDGE/DB/VECTOR는 재생성 가능한 파생물입니다.

2
Deterministic 처리와 LLM 해석 분리

RAW→ANALYSIS→KNOWLEDGE INPUT에는 생성형 LLM을 넣지 않습니다.

3
Issue가 지식화 중심 허브

Comment, Attachment, Relationship, Custom Field를 Issue에 연결해 문맥을 완성합니다.

4
Custom Field = Catalog + Values

새 field_id가 늘어도 DB schema migration을 최소화하는 row 기반 모델을 유지합니다.

5
새 Schema는 실패가 아니라 관찰 대상

Known handler → generic safe fallback → warning/observation 순서로 흡수합니다.

6
PII 복제 최소화

emailAddress/avatarUrls/timeZone/self 등은 RAW에 남기고 필요한 표시/식별 정보만 ANALYSIS로 가져옵니다.

7
Knowledge는 evidence 추적 가능해야 함

Knowledge Item → KNOWLEDGE INPUT → ANALYSIS → RAW로 역추적할 수 있어야 합니다.

8
MCP는 deterministic retrieval

검색·필터·원문 복원·근거 반환에 집중하고 최종 질문 해석/답변은 상위 Agent가 맡습니다.
