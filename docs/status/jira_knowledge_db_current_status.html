6. 구현 전에 남은 아키텍처 정책

Intermediate Version supersede

V2→V3→V4가 Processing 전에 쌓였을 때 미시작 구버전 Work를 모두 처리할지, 최신 pending을 우선하고 구버전을 supersede할지 결정해야 합니다.

Multi-worker claim / lease

초기 Single Worker. 병렬 Processing이 실제로 필요해질 때 별도 결정합니다.

현재 가장 가까운 다음 결정

Intermediate Version supersede 정책을 먼저 결정한 뒤 State Schema v2 Migration/StateStore 구현으로 들어가는 것이 좋습니다.
