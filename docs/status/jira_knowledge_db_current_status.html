M6 현재 · DB Logical Schema

M6는 SQLite 구현이 아니라 논리 설계 단계입니다. M6-01에서 Issue identity, 의미 변경 Version, Knowledge Generation history, Active Retrieval 경계를 먼저 확정했습니다.

Pipeline Run │ └── Version Observation │ Issue ── 1:N Issue Version │ └── 1:N Knowledge Generation ├── active ├── historical │ ├── Knowledge Item │ └── Knowledge Evidence │ └── Source Entity round-trip └── Knowledge Review └── Review Finding

M6-01 · Version

source_hash가 같으면 Version을 새로 만들지 않습니다. 변경된 Issue만 새 issue_version을 추가합니다.

History

Historical Version/Knowledge는 삭제하지 않고 당시 Evidence 재현, 감사, 변화 분석을 위해 DB에 보존합니다.

Active Retrieval

기본 RAG/FAISS에는 승인된 active Current Knowledge만 포함합니다. Historical Knowledge는 기본 검색에서 제외합니다.

Same Version · New Generation

원문이 같아도 Skill/Schema/Model extraction contract가 바뀌면 같은 Issue Version에 새로운 Knowledge Generation을 만들 수 있습니다.

Evidence

knowledge_item → knowledge_evidence → issue version / comment / attachment / relationship / custom field round-trip을 보존합니다.

Next · M6-02

issue_version_id, knowledge_generation_id, knowledge_item_id의 deterministic canonical ID 규칙을 확정합니다.

M6-01 DECIDEDRun별 Snapshot 복제 초안은 폐기했습니다. source_hash changed → new issue_version, History storage ≠ Active retrieval corpus를 공식 원칙으로 채택했습니다.

현재 고정 결정사항

  • RAW는 Source of Truth
  • ANALYSIS는 deterministic normalization
  • Knowledge는 검색용 의미 압축, 사실 원장 아님
  • Knowledge Schema v0.1 / Skill v0.9 유지
  • Reviewer score는 품질 인증서가 아니라 결함 감소 지표
  • M6-01: source_hash 변경 시에만 새 Issue Version 생성
  • Historical Version/Knowledge는 DB에 보존
  • 기본 FAISS/RAG는 active Current Knowledge만 사용
  • 같은 Version에 extraction contract별 여러 Generation 허용
  • Evidence round-trip을 DB 핵심 계약으로 유지
  • Vector ID는 authoritative identity가 아님

Definition of Done

Functional MVP · M10

기능적으로 끝까지 된다

  • SQLite Knowledge→Evidence→원문 round-trip
  • BGE-M3/FAISS Active Top-k 검색
  • MCP가 결정적으로 Evidence 반환
  • 상위 Agent가 근거 포함 답변 가능
Operational System · M16

사람 개입 없이 안전하게 유지된다

  • 증분 sync/rebuild
  • retry/resume/active publish/rollback
  • 관측/알림
  • backup/restore/runbook
