M6 현재 · DB Logical Schema

M6는 SQLite 구현이 아니라 논리 설계 단계입니다. 기존 ANALYSIS/KNOWLEDGE 계약을 유지하면서 질의 가능하고 Evidence round-trip이 가능한 Entity와 ID 체계를 확정합니다.

Pipeline Run │ ├── Issue ── Issue Snapshot │ ├── Comment │ ├── Attachment │ ├── Custom Field Value │ └── Relationship │ └── Knowledge Generation ├── Knowledge Item │ └── Knowledge Evidence │ └── Source Entity round-trip └── Knowledge Review └── Review Finding

Identity

run_id, issue_key, comment_id, attachment_id, relationship_id, field_id를 원본 식별자로 유지합니다. DB surrogate key는 내부 편의용입니다.

Knowledge

6개 category는 generic knowledge_item으로 모델링하고 issue_summary도 같은 table에서 category로 구분하는 기본안을 검토합니다.

Evidence

knowledge_item → knowledge_evidence → issue/comment/attachment/relationship/custom field 경로를 보존합니다. exact evidence_ref도 그대로 저장합니다.

Version

run_id, Knowledge Input source_hash, schema/skill version을 보존해 향후 증분 rebuild 판단에 사용할 수 있게 합니다.

Review Audit

최종 PASS만 남기지 않고 모든 Attempt와 Critical/Major/Audit finding을 query 가능한 형태로 보존합니다.

아직 하지 않음

SQLite DDL, Chunk table, Embedding/FAISS, index 튜닝은 M6 범위가 아닙니다.

현재 고정 결정사항

  • RAW는 Source of Truth
  • ANALYSIS는 deterministic normalization
  • Knowledge는 검색용 의미 압축, 사실 원장 아님
  • Knowledge Schema v0.1 / Skill v0.9 유지
  • Reviewer score는 품질 인증서가 아니라 결함 감소 지표
  • 최종 Run 통계는 deterministic code가 담당
  • Evidence round-trip을 DB 핵심 계약으로 유지
  • Vector ID는 authoritative identity가 아님
  • 현재 30건 p95/max를 DB hard limit로 사용하지 않음
  • 기존 유효 문서는 단계별 산출물로 누적 보존

Functional MVP · M10

기능적으로 끝까지 된다

  • SQLite Knowledge→Evidence→원문 round-trip
  • BGE-M3/FAISS Top-k 검색
  • MCP가 결정적으로 Evidence 반환
  • 상위 Agent가 근거 포함 답변 가능

사람 개입 없이 안전하게 유지된다

  • retry/resume/rollback
  • 관측/알림
  • backup/restore/runbook
