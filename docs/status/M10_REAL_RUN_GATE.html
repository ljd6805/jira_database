두 검증을 모두 통과해야 “실제로 사용할 수 있다”고 판단할 수 있습니다.

비유 공장에서 엔진 단품 검사는 끝났지만, 실제 차체에 넣고 시동이 걸리는지 확인하는 최종 시운전입니다.

1. 실제로 검증되는 경로

M10_REAL_RUN_QUERY ↓ 사내 BGE-M3 ↓ 1024-d query vector M9 index.faiss ↓ Top-3 RetrievalCandidate embedding_id → knowledge_item_id(ki_) ↓ M7 SQLite ↓ active + accepted 재검증 ki_ → ke_ → actual source row ↓ Evidence Package ↓ MCP search_jira_knowledge ↓ 첫 결과의 issue key 내부 사용 MCP get_jira_issue ↓ Gate validation

2. 준비할 환경 변수

변수의미공개 문서에 값 기록?
JIRA_KNOWLEDGE_DB_PATHM7 validation SQLite 파일아니요
JIRA_RETRIEVAL_ARTIFACT_DIRM9 index.faiss / mapping / manifest 디렉터리아니요
BGE_M3_ENDPOINT실제 query embedding endpoint아니요
BGE_M3_API_KEY필요한 경우 인증 값절대 안 됨
BGE_M3_HEADERS_JSON필요한 경우 사내 custom header절대 안 됨
M10_REAL_RUN_QUERY실제 데이터에서 결과가 나올 것으로 기대하는 질문아니요
중요: M10_REAL_RUN_QUERY는 자동으로 채워지는 값이 아닙니다. 파일럿 30개 Jira 안에 관련 내용이 있을 것으로 기대하는 실제 질문 1개를 직접 넣어야 합니다.

3. Query를 안전하게 설정하기

실제 Jira 업무 질문이 shell history에 남지 않도록 read로 입력하는 방법을 권장합니다.

read -r -p "M10 test query: " M10_REAL_RUN_QUERY export M10_REAL_RUN_QUERY test -n "$M10_REAL_RUN_QUERY" && echo "M10 query: SET" || echo "M10 query: EMPTY"

화면에도 질문이 보이지 않게 하려면 아래처럼 read -s를 사용합니다.

read -s -r -p "M10 test query: " M10_REAL_RUN_QUERY; echo export M10_REAL_RUN_QUERY
왜 CLI argument가 아닌가? 실제 Jira 업무 내용이 들어갈 수 있는 질문을 --query "..." 형태로 shell history에 남기지 않기 위해 환경변수로 전달합니다.

4. 실행

python3 tools/jira_knowledge/validate_m10_real_run.py

검증 후 질문 변수를 지우려면 unset M10_REAL_RUN_QUERY를 실행합니다.

5. PASS 출력 형태

tool_count: 2 search_result_count: 1~3 evidence_count: 1 이상 warning_count: 0 path_leak_count: 0 issue_lookup_ok: true failure_count: 0 M10_REAL_RUN = PASS
원문은 출력하지 않습니다. Gate 로그에 남기는 것은 위와 같은 안전한 집계뿐입니다.

6. PASS 기준

□ MCP tool surface = 정확히 2개
□ search 결과가 1건 이상 존재
□ 각 result에 statement 존재
□ 각 result에 Evidence 1개 이상 존재
□ warning_count = 0
□ path_leak_count = 0
□ 첫 검색 결과 Issue가 get_jira_issue로 round-trip
□ 최종 failure_count = 0

8. Real-run에서 하지 않는 것

LLM 답변 품질 평가

M10 Gate는 Evidence/MCP 파이프라인 검증입니다. Agent가 얼마나 자연스럽게 답하는지는 별도 상위 레벨 평가입니다.

Threshold/Reranker 튜닝

Real-run에서 후보 하나가 어색하다는 이유만으로 M9 계약을 즉시 바꾸지 않습니다.

Production delta 구현

IndexIDMap2, vector cache, HNSW/IVF는 별도 production-hardening입니다.

실제 데이터 Git 기록

Query, Issue key, source text, endpoint/header/token을 공개 저장소 문서에 남기지 않습니다.
