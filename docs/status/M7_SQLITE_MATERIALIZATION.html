DB 전체 구성·연결도는 M6 시각 문서를 기준으로 합니다. M7은 그 논리 구조를 아래 제약으로 실제 구현했습니다.

knowledge_itemUNIQUE(knowledge_attempt_id, category, ordinal)
knowledge_evidenceitem+ordinal 및 item+exact evidence_ref UNIQUE

4. Materializer가 실제로 하는 순서

1. ANALYSIS Run load 2. Knowledge Input manifest / Issue package load 3. 최종 Knowledge artifact load 4. Attempt별 Review artifact load 5. Issue 집합 일치 검증 6. SQLite Schema 초기화 7. Run-scoped source Entity 적재 8. issue_version + observation 생성/재사용 9. Generation + Attempt lineage 생성 10. accepted Attempt의 Knowledge Item / Evidence 적재 11. Review / Finding 이력 적재 12. accepted Evidence source round-trip 검증 13. 하나라도 실패하면 transaction rollback

5. Legacy M4 Attempt를 거짓 복원하지 않는다

Attempt 1 FAIL → Attempt row + Review / Finding → content_available = false Accepted Attempt N PASS → Attempt row + Review / Finding → Knowledge Item / Evidence → content_available = true → accepted_attempt_id → Generation active
M4에는 failed Attempt 당시 Knowledge body가 남지 않았습니다. M7은 존재하지 않는 본문을 추정해 채우지 않고 “콘텐츠 없음” 자체를 정확히 저장합니다.
