1. 목적과 경계

M0의 성공 기준은 지식을 잘 추론하는 것이 아니라, LLM이 개입하기 전 사실 데이터가 완전하고 재현 가능한가였습니다.

Jira REST API ↓ 읽기 전용 Collector ↓ [RAW] 원본 JSON snapshot ↓ Parser / Exporter ↓ [ANALYSIS] 정규화 JSONL
RAW First

원본 snapshot이 사실 기준. Parser 오류가 나도 Jira 재호출 없이 재처리합니다.

Collector / Parser 분리

외부 통신과 로컬 결정적 변환을 분리해 책임과 재현성을 명확히 했습니다.

안전성 우선

쓰기 금지, 비밀정보 분리, atomic store, checkpoint, rate limit을 속도보다 우선했습니다.

3. RAW / ANALYSIS 계약

RAW

data/raw/runs/<run_id>/projects/<project_key>/ ├─ project.json ├─ issue_search/page_*.json └─ issues/<issue_key>/ ├─ issue.json └─ comments/page_*.json

ANALYSIS

issues.jsonl comments.jsonl attachments.jsonl issue_relationships.jsonl custom_field_catalog.jsonl custom_field_values.jsonl summary.json parse_warnings.jsonl

Issue Link와 Parent/Subtask는 canonical edge로 정규화하고, Custom Field는 Catalog 정의와 Issue별 실제 값을 분리했습니다. Plugin field는 schema만 보고 타입을 단정하지 않고 schema_type / actual_type / value_kind를 구분합니다.
