5. 가장 중요한 Transaction

T3 · Project Source Commit BEGIN source_project_run source_status = source_committed project_state committed_watermark = upper 이번 Source Run의 NEW/CHANGED Work last_source_committed_run_id = current → Source Ready 같은 jira_id의 이전 pending / failed / running Work → work_status = superseded → superseded_by_work_item_id = latest COMMIT

이 Transaction이 실패하면 Watermark만 앞서가거나, 아직 Commit되지 않은 최신 Version 때문에 기존 Work가 먼저 superseded되는 상태가 생기지 않습니다.

6. Loop B foundation도 준비했습니다

Latest backlog

list_latest_ready_work_items()는 Source Ready + pending/failed + not superseded만 반환합니다.

Single Worker claim

claim_work_item(). 아직 Multi-worker lease는 도입하지 않습니다.

Stale guard

work_item_is_latest()를 OpenCode 결과 후와 Publish 직전에 다시 사용할 수 있습니다.

claim 직전 latest check → OpenCode → 응답 직후 latest check → Knowledge / Embedding → Publish 직전 latest check → Atomic Publish

7. A → B → A도 처리합니다

Source semantic state A → B → A 첫 A → Knowledge completed → Embedding completed → Published B → 새 Work A가 다시 최신 → 기존 A의 같은 sw_ 재사용 → Knowledge/Embedding 재사용 → Publish만 pending으로 재활성화 → 미완료 B는 superseded

semantic identity와 expensive artifact를 불필요하게 다시 만들지 않습니다.
