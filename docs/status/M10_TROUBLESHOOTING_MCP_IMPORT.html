ModuleNotFoundError:
No module named 'mcp'

M10 Real-run 실행 시 현재 Python 환경에 MCP Python SDK가 설치되지 않았을 때 발생한 환경 오류입니다.

RESOLVED IN REAL-RUN · CODE CONTRACT UNCHANGED

원인

프로젝트의 pyproject.toml에는 mcp>=2.0,<3.0이 dependency로 정의되어 있습니다. 따라서 로컬 checkout이 오래됐거나, 최신 checkout 이후 현재 Python 환경에서 프로젝트 dependency를 다시 설치하지 않은 경우가 가장 유력합니다.

현재 테스트 환경

Windows PowerShell 권장 복구 순서

cd jira_database git pull python --version python -m pip install -e ".[dev]" python -c "import mcp; print('mcp OK:', mcp.__file__)" python tools/jira_knowledge/validate_m10_real_run.py

프로젝트는 Python 3.11 이상을 요구합니다. pip 단독 명령보다 python -m pip를 사용해 실행 interpreter와 설치 interpreter를 일치시키는 것이 중요합니다.

Windows에서 그래도 실패하면

Get-Command python python -m pip --version python -m pip show mcp python -c "import sys; print(sys.executable); print(sys.path)"

pip show mcp가 성공하는데 import가 실패하면 서로 다른 Python/virtualenv를 사용 중일 가능성이 높습니다.

향후 Linux 포팅 시

which python3 python3 -m pip install -e '.[dev]' python3 -m pip show mcp python3 -c "import mcp; print('mcp OK:', mcp.__file__)"

이번 실전에서 확인된 사실

✓ 이 오류는 MCP 코드 로직 오류가 아니라 dependency/environment 문제였다.
✓ MCP import가 성공한 뒤 다음 Real-run precondition 검사로 진행됐다.
✓ 이후 Query와 Runtime path를 설정한 뒤 최종 Real-run PASS까지 도달했다.
