1. 원래 구현한 Embedding 범위

Generation 단위 Corpus

load_generation_embedding_corpus()가 accepted Knowledge Item을 deterministic 순서로 읽습니다.

Latest-only BGE-M3

OperationalEmbeddingWorker는 Source-ready/latest Work만 처리합니다.

Atomic staging artifact

corpus.jsonl, embeddings.jsonl을 임시 파일 후 atomic replace합니다.

Independent Processing Run

Embedding stage도 별도 processing_run으로 실행되며 Publish가 이어받도록 완료 후 Work를 pending으로 돌립니다.

2. 의도한 안전 순서

Knowledge checkpoint completed → Incremental Knowledge DB candidate + accepted_attempt_id → latest / Source Ready 확인 → embedding_status = running → Generation corpus 생성 → BGE-M3 호출 → latest 재확인 → embeddings.jsonl atomic 저장 → latest 재확인 → embedding_status = completed → work_status = pending → Publish stage

3. 자동 테스트에서 실제 검증된 것

Embedding Worker success

준비된 candidate Generation을 fake client로 임베딩.

Stale race

BGE 응답 전 newer Source Commit 시 old Work completed 차단.

Retry

API 실패 시 latest Work가 retry 가능한 상태로 남음.

Processing Run

Embedding 완료 후 Publish 전 상태를 partial/pending으로 유지.

Artifact

Corpus/Embedding 파일이 정상 생성된 뒤 State completed.

Coverage Gap

실제 IncrementalKnowledgeDbMaterializer → 현재 loader.py 연결은 자동 테스트에서 검증하지 않았습니다.
