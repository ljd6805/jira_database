jira_database 프로젝트 루트 ├─ .env ├─ data/ ├─ MCP code └─ opencode.jsonc ↓ OpenCode가 child process로 local stdio MCP 실행 ↓ python -m jira_collector.mcp_server.server ↓ CONNECTED

Local stdio MCP는 사용자가 서버를 미리 실행해 두는 구조가 아닙니다. OpenCode가 command를 보고 MCP child process를 직접 기동합니다.

2. 왜 다른 프로젝트에서는 처음 실패했나?

다른 프로젝트 루트 └─ opencode.jsonc cwd = "." ↓ OpenCode workspace = 다른 프로젝트 ↓ MCP cwd도 다른 프로젝트 ↓ jira_database/.env / config / 상대 artifact 기준과 불일치 ↓ Connection closed

cwd="."는 MCP 저장소의 위치가 아니라 OpenCode를 실행한 workspace를 의미합니다. 따라서 local Pilot은 우선 jira_database 안에서 검증하는 것이 가장 단순합니다.

6. OpenCode 1.18.12 Remote MCP 호환성

Remote 설정 지원

type="remote", url, headers, oauth, timeout을 지원합니다.

Transport

Remote 연결에서 Streamable HTTP를 먼저 시도하고 실패 시 SSE를 시도합니다.

현재 MCP Python SDK 2.1.1의 MCPServer도 stdio, sse, streamable-http 실행을 지원하므로 기존 Tool/Service 계층을 유지한 채 서버 transport를 확장할 수 있습니다.

8. 왜 Remote 서버화를 지금 바로 하지 않나?

기능 경계를 먼저 닫습니다.

Tool discovery/call/answer 활용까지 local에서 확인한 뒤 서버화하면, 이후 문제가 발생했을 때 MCP 기능 문제와 HTTP/TLS/인증/운영 문제를 분리할 수 있습니다.

M11 local functional Pilot 완료 ↓ Post-M11 Remote MCP Service Streamable HTTP → 인증/TLS → 중앙 배포 → 팀원 remote OpenCode 연결 → logging/health/concurrency → 팀 Pilot
