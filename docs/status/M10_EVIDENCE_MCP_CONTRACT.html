1. 확정 결정 6개

✓ 후보 중심 Evidence Package
✓ M7의 6종 Evidence 계약 재사용
✓ Runtime candidate 단위 오류 격리
✓ M9 Top-3 + canonical Evidence 우선 전부
✓ MCP는 search + get_issue 2 tools
✓ ki_ active accepted lineage 재검증

2. Evidence Package 계약

candidate package ├─ rank / score ├─ faiss_position ├─ embedding_id (emb_) ├─ knowledge_item_id (ki_) ├─ category ├─ statement ├─ issue │ ├─ issue_key │ ├─ status │ └─ issue_type └─ evidence[] ├─ knowledge_evidence_id (ke_) ├─ evidence_ref / type ├─ source_issue_key ├─ source_entity_key ├─ text / format └─ type-specific metadata
외부 응답에 넣지 않음 source_path, source_page, 로컬 DB 경로, 사내 endpoint/header/secret은 Evidence Package나 MCP 응답에 노출하지 않습니다.

3. Resolver 계약

typesource반환 핵심
summaryissue_version.summarytext
descriptionissue_version.descriptiontext, format
commentcommentcomment_id, author, time, body, format
attachmentattachmentid, filename, mime, size, content_available
relationshiprelationshiptype/text, source/target issue
custom_fieldcustom_field_value + catalogfield id/name, display value(s)

M7의 parse_evidence_ref() 규칙과 동일한 source identity를 사용합니다. M10은 새 Evidence 문법을 만들지 않습니다.

4. Active / stale 규칙

M9 candidate ki_ ↓ knowledge_item → knowledge_attempt → knowledge_generation ↓ 정상 사용 조건 - generation.state = active - generation.accepted_attempt_id = item.knowledge_attempt_id - attempt.content_available = 1
stale이면 조용히 사용하지 않습니다. M9 index와 M7 DB의 snapshot이 어긋난 경우 해당 candidate를 제외하고 구조화된 warning으로 드러냅니다.

5. Runtime 실패 정책

정상 candidate → results[] 깨진 Evidence candidate → 제외 + warnings[] stale candidate → 제외 + warnings[] 모든 candidate 실패 → typed error Offline / CI Gate accepted Evidence missing > 0 → FAIL stale active lineage > 0 → FAIL local path leak > 0 → FAIL

한 candidate가 깨졌다고 정상 candidate까지 버리지는 않지만, 실데이터 Gate에서는 이런 깨짐이 0건이어야 합니다.

6. Candidate / Evidence Budget

Pilot 기준: M9 default Top-3를 유지하고 각 Knowledge Item에 연결된 canonical Evidence를 우선 모두 포함합니다.

cosine threshold, reranker, Evidence N개 제한을 근거 없이 추가하지 않습니다. 실제 M10 payload와 답변 품질을 본 뒤 필요한 최소 제한만 추가합니다.

7. MCP Surface

search_jira_knowledge

query → M9 retrieval → M10 resolve → Evidence Package. 일반 자연어 질문의 주 도구입니다.

get_jira_issue

issue_key를 알고 있거나 검색 결과를 더 깊게 확인할 때 current issue snapshot과 근거 source를 제공합니다.

MCP 내부 생성형 LLM 없음. MCP는 검색과 Evidence 복원까지만 담당하고 최종 설명은 Agent의 LLM이 수행합니다.
