M9 DECISION LOG · 2026-08-26

FAISS + Active Retrieval
의사결정 기록

M9-01은 승인되어 설계가 고정됐고, M9-02 구현과 synthetic CI까지 완료했습니다.

M9-01 · APPROVED / DESIGN FROZEN

D1 · Index

IndexFlatIP = current exact baseline / test oracle

285개에서는 exact exhaustive search를 사용합니다. 향후 규모가 커지면 Flat 결과를 정답 기준으로 HNSW/IVF의 recall@k와 latency를 비교합니다.

D2 · Similarity

cosine = L2 normalize(database) + L2 normalize(query) + inner product

M8 vector가 이미 정규화됐다고 가정하지 않고 FAISS용 복사본을 정규화합니다.

D3 · Query

query_text_profile = raw_query_v1 query_text = query.strip() same model/profile/dimension as M8

D4 · Candidate policy

Top-k = 3 threshold = none reranker = none

M8의 dense-neighborhood 관찰 때문에 Top-1 하나를 과신하지 않습니다.

D5 · Mapping

faiss_position → embedding_id → knowledge_item_id canonical order = embedding_id ascending

FAISS position은 stable identity가 아닙니다.

D6 · Artifact

index.faiss index.mapping.jsonl index.manifest.json

Manifest를 마지막에 publish해 완료 marker로 사용합니다.

D7 · Identity

Retrieval Contract rc_ FAISS Index Artifact fi_

D8 · Update

new active embedding snapshot → full rebuild

Pilot에서는 incremental mutation보다 재현성과 stale-vector 제거를 우선합니다.

D9 · M10 boundary

M9 = rank + score + position + emb_ + ki_ M10 = Knowledge/Evidence resolve + MCP
M9-01 = DESIGN FROZEN

M9-02 · IMPLEMENTED / CI PASS

numpy >= 1.26, < 3.0 faiss-cpu >= 1.15, < 2.0

M9 build 직전에 현재 M8 corpus/embedding integrity를 다시 검증합니다.

Query API 호출 전에 BGE-M3 model/profile/dimension이 manifest와 동일한지 검사합니다.

I6 · CI Gate
