# Windows 파일 잠금 대응

Jira Raw Data Collector는 JSON을 직접 최종 파일에 쓰지 않습니다.
먼저 같은 디렉터리의 임시 파일에 기록하고 `flush`와 `fsync`를 수행한 뒤,
`os.replace()`로 최종 파일명을 원자적으로 교체합니다.

Windows에서는 Defender, 사내 백신, OneDrive, 파일 탐색기 미리보기 또는 다른 수집기 프로세스가
파일을 잠깐 점유할 수 있습니다. 이때 다음 오류가 발생할 수 있습니다.

```text
[WinError 32] 다른 프로세스가 파일을 사용 중이기 때문에 프로세스가 액세스 할 수 없습니다
```

## 현재 복구 정책

`RawStore`는 Windows의 일시적인 파일 잠금 오류를 다음 코드로 판별합니다.

- WinError 5: Access denied
- WinError 32: Sharing violation
- WinError 33: Lock violation

해당 오류가 `os.replace()`에서 발생하면 최대 6회까지 지수 backoff로 다시 시도합니다.

```text
0.2초 → 0.4초 → 0.8초 → 1.6초 → 2.0초
```

최대 약 5초 동안 재시도한 뒤에도 파일이 잠겨 있으면 원래 예외를 다시 발생시킵니다.
Windows 파일 잠금과 무관한 권한 오류는 즉시 실패하며 재시도하지 않습니다.

임시 파일 삭제가 실패하더라도 정리 단계의 오류가 최초 저장 오류를 덮어쓰지 않도록
경고만 기록합니다.

## 운영 시 확인할 사항

재시도 후에도 오류가 반복되면 다음을 확인하십시오.

1. `jira-collector` 또는 Python 수집 프로세스가 두 개 이상 실행 중인지 확인
2. `storage.data_root`가 OneDrive 또는 네트워크 드라이브인지 확인
3. 백신 실시간 검사 또는 동기화 대상 폴더인지 확인
4. 파일 탐색기 미리보기나 에디터가 대상 JSON을 열고 있는지 확인
5. 가능하면 `C:/jira-data` 같은 일반 로컬 디렉터리를 데이터 경로로 사용

이 재시도는 짧은 일시적 잠금을 복구하기 위한 기능입니다.
여러 수집기 프로세스가 동일한 run 경로에 계속 쓰는 구조를 안전하게 만들어 주지는 않습니다.
파일럿에서는 수집 프로세스를 하나만 실행하십시오.
