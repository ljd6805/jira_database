최소 구현 계획

프로젝트 초기에는 “Jira 원문을 보존하고, BGE-M3와 FAISS로 관련 근거를 찾고, MCP가 그 근거를 Agent에게 제공한다”는 최소 한 바퀴를 목표로 시작했습니다. 이 문서는 그 출발점을 현재 Jira Knowledge Pipeline 문서 체계 안에 연결한 버전입니다.

2. 초기 계획에서 확정했던 조건

Jira 접근

ID/Password 기반 읽기 API 통신을 사용하고, 운영 목표는 인증 계정이 조회 가능한 모든 프로젝트입니다. 파일럿은 프로젝트별 최근 수정 이슈 30개였습니다.

BGE-M3

사내 OpenAI-compatible embedding API를 사용합니다. 당시 확인한 핵심 제약은 HTTP 200회/분, batch 최대 64, dense dimension 1024였습니다.

LLM 경계

생성형 LLM은 Agent 쪽에만 둡니다. MCP는 검색·필터·원문 복원·출처 반환에 집중하고 최종 답변을 먼저 생성하지 않습니다.

초기 핵심 문장
“Jira 원문을 보존하고 검색 가능한 형태로 색인한 뒤, MCP는 관련 원문과 출처를 반환하고 Agent LLM이 그 근거를 분석해 답한다.”
