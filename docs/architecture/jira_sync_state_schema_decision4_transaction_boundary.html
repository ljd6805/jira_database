S4 · CURRENT TRANSACTION BOUNDARY

짧은 Commit Point 원칙을 유지하고,
Ready + supersede를 같은 transaction에서 확정합니다.

Loop A · Source Transaction

A0 Source Run Start → source_sync_run + fixed upper durable A1 Discovery Commit → 완전한 Discovery snapshot일 때만 project_state 변경 A2 Per-Candidate actual Source files durable → Work Item row INSERT/UPSERT → last_observed_source_run_id = current → count + stable cursor SAME State transaction → 아직 Processing eligibility 없음 A3 Project Commit · 핵심 같은 State DB transaction에서 1. source_project_run.source_status = source_committed 2. project_state.committed_watermark = upper 3. 새 Work Item last_source_committed_run_id = current last_source_committed_at = now 4. 같은 jira_id의 이전 미완료 Work work_status IN (pending, failed, running) → work_status = superseded → superseded_by_work_item_id = new work → superseded_at = now → COMMIT A4 Source Run Finalize → discovery/source/run status 집계

Source Ready + Latest Gate

Loop B claim 가능 last_source_committed_run_id IS NOT NULL AND last_source_committed_run_id = last_observed_source_run_id AND work_status IN ('pending','failed') AND superseded_by_work_item_id IS NULL

A2에서 row가 만들어져도 A3 Project Commit 전에는 Source Ready가 닫혀 있습니다. A3에서 더 최신 Work가 확정되면 이전 미완료 Work의 latest 자격도 같은 순간에 제거합니다.

Loop B · Processing Transaction

B0 Processing Run Start → processing_run row durable B1 Claim → latest + Source Ready Work만 선택 B2 OpenCode 호출 전 latestness check B3 Knowledge actual Knowledge DB result first → OpenCode 응답 후 latestness re-check → stale이면 Active 처리 중단 → 최신이면 State knowledge_status = completed B4 Embedding actual vector/artifact first → State embedding_status = completed second B5 Publish Publish 직전 latestness re-check → actual Retrieval active switch first → verify → State publish_status/work_status = published second B6 Processing Run Finalize → selected / published / failed / superseded counts

두 Loop를 하나의 Transaction으로 묶지 않습니다

Loop A Source Commit 이후 Loop B는 나중에 별도 프로세스/스케줄로 실행될 수 있습니다. 두 Loop 사이의 durable 경계는 sync_issue_change row + Ready/Latest 조건입니다.

최우선 불변식

Watermark는 Source Commit보다 먼저 가지 않는다. Ready Gate는 Source Commit보다 먼저 열리지 않는다. 새 latest Work와 old-work supersede는 같은 State transaction에서 확정한다. Loop B는 superseded Work를 claim하지 않는다. stale in-flight 결과는 Publish하지 않는다. State completed/published는 실제 durable 결과보다 먼저 가지 않는다. Loop A 성공은 Loop B 성공을 기다리지 않는다.
