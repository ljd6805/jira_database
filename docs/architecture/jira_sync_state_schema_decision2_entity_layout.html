Operational Domain Table은 4개에서 5개로 revision되었습니다.

기존 S2는 project registry/state를 합쳐 4개 테이블로 정리했습니다. 2-Loop 채택으로 별도 processing_run이 필요해져 현재 물리 Domain Table은 5개입니다.

v1 baseline

sync_run project_state sync_project_run sync_issue_change

현재 v2

1. source_sync_run 2. project_state 3. source_project_run 4. sync_issue_change 5. processing_run

논리 역할

source_sync_run은 Loop A 실행, processing_run은 Loop B 실행, sync_issue_change는 두 Loop 사이 durable backlog입니다. project_state는 여전히 Project identity/visibility/watermark를 한 행으로 보유합니다.
