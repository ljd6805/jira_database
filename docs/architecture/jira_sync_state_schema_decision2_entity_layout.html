S2 · CURRENT ENTITY LAYOUT

Operational Domain Table은 현재 5개입니다.

2-Loop를 채택하면서 Source 실행과 Processing 실행을 분리했고, Latest-Only 정책이 추가된 현재 개정 3에서도 5개 테이블 경계는 그대로 유지됩니다.

과거 설계 · 개정 1

sync_run project_state sync_project_run sync_issue_change

하나의 sync_run이 Source와 Publish 상태를 함께 들고 있던 설계입니다. 실제 배포 전 폐기되었습니다.

현재 Operational State 설계 · 개정 3

1. source_sync_run 2. project_state 3. source_project_run 4. sync_issue_change 5. processing_run

개정 2에서 5개 테이블 구조가 만들어졌고, 개정 3은 같은 구조에 Latest-Only lifecycle 필드를 추가했습니다.

각 테이블의 역할

source_sync_run은 Loop A 실행, processing_run은 Loop B 실행, sync_issue_change는 두 Loop 사이 durable backlog입니다. project_state는 Project identity/visibility/watermark, source_project_run은 Source Run×Project 진행 상태를 보관합니다.

버전 번호 주의

여기서 개정 3은 Operational State DB의 개정 번호입니다. Knowledge DB Schema 개정 1과 비교하는 숫자가 아닙니다.
