한 번의 Sync가
성공했는지 어떻게 말할까?

Run 상태는 이번 실행의 진척을 표현합니다. 기존 Published Knowledge 서비스의 생존 여부와는 별개입니다.

FIXED · COMPLETED / PARTIAL / FAILED

1. 내부 상태를 따로 봅니다

discovery_status + source_status + publish_status ↓ run_status

Project 목록을 신뢰할 수 있는지, Source를 어디까지 commit했는지, Publish를 어디까지 끝냈는지 따로 기록한 뒤 최종 Run 상태를 집계합니다.

2. 최종 상태

COMPLETED

Discovery 성공 + 모든 visible Project Source Commit 완료 + 필요한 Publish 모두 완료 또는 not_required.

PARTIAL

하나 이상의 durable 성공 결과가 있지만 Source 또는 Publish에 실패/미완료가 남음.

FAILED

Discovery 결과를 신뢰할 수 없거나 처리 대상 Source 범위에서 durable Source progress를 하나도 만들지 못함.

3. 중요한 예외

상황Run 상태
변경 0건, 모든 visible Project 정상 확인completed
Source 전부 성공, Publish 일부/전부 실패partial
Project A/C 성공, B 실패partial
Project Discovery 자체 실패/불완전failed
모든 visible Project Source 실패failed
기존 Project unavailable실패로 세지 않고 skip

4. Run 실패와 Knowledge 서비스 실패는 다릅니다

이번 Sync Run = FAILED 하지만 기존 Published Knowledge = 그대로 기존 Embedding / FAISS = 그대로 MCP Retrieval = 그대로
확정: failed는 이번 Sync가 새 Source 진척을 만들지 못했다는 뜻입니다. 기존 지식 제공을 자동 중단하지 않습니다.

5. Decision 8 최종 규칙

COMPLETED = 이번 책임 범위를 모두 완료 PARTIAL = durable progress 있음 + 남은 미완료 있음 FAILED = Discovery 불신뢰 또는 durable Source progress 없음 UNAVAILABLE Project = SKIPPED_UNAVAILABLE = Run 실패 아님 = 기존 Knowledge Retrieval 유지
