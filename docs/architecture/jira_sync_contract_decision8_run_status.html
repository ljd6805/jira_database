HISTORICAL DECISION · REVISED 2026-08-28

D8의 “단일 Sync Run 상태”는 D9 2-Loop로 revision되었습니다.

2026-08-27 D8은 Source와 Publish를 하나의 Sync Run에서 집계했습니다. 이후 Source Sync와 Knowledge Processing/Publish를 독립 Loop로 운영하기로 확정하면서 그 집계 단위가 더 이상 맞지 않게 되었습니다.

원래 D8

COMPLETED = Discovery success + all visible Project Source Commit + all Publish complete / not_required PARTIAL = durable progress 있음 + 일부 Source/Publish 미완료 FAILED = Discovery 불신뢰 또는 Source durable progress 없음

현재 D8 의미

Runcompletedpartialfailed
source_sync_runDiscovery 신뢰 + 모든 visible Project Source 책임 완료일부 Source progress + 일부 실패Discovery 불신뢰 또는 필요한 Source progress 없음
processing_run선택한 Work Item 전체 완료 또는 Work 0일부 processing progress + 일부 실패/미완료의미 있는 processing progress 없이 실패

왜 바뀌었나?

OpenCode가 느린 시간대에도 Jira Source 최신화를 계속하기 위해 Loop A와 Loop B가 서로 기다리지 않도록 했기 때문입니다. 따라서 하나의 Run이 Source와 Publish를 동시에 대표할 수 없습니다.

시스템 전체 상태

단일 run_status 사용 X Source Lag Publish Lag Backlog Depth Oldest Pending Age Processing Throughput / Error → 이 지표 조합으로 운영 상태 판단
