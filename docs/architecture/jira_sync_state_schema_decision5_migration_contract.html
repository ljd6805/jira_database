S5 · CURRENT MIGRATION CONTRACT · REVISED 2026-08-31

Migration은 기본 경로가 아니라
legacy DB 재사용을 위한 호환 경로입니다.

현재 공식 Real Test / 운영 시작 정책은 Fresh Bootstrap입니다. 기존 파일럿 collector.db를 꼭 이어써야 하는 특별한 경우에만 explicit Migration을 사용합니다.

현재 공식 시작 방식

Smoke → data_smoke/ 새 DB → Migration 없음 Formal Real Test → 기존 파일럿 DB 삭제 또는 별도 보관 → 빈 ./data에서 새 DB 생성 → Migration 없음 → Full Initial Ingest Legacy Reuse Exception → 기존 collector.db를 계속 사용해야 함 → explicit Migration REQUIRED

사람용 이름과 SQLite 기술 값

현재 Operational State 설계 · 개정 3 STATE_SCHEMA_VERSION = 3 PRAGMA user_version = 3

Fresh Bootstrap에서도 같은 Schema 개정 3이 생성됩니다. Migration 여부와 Schema 버전은 별개입니다.

Migration이 필요한 경우에만 적용하는 절차

legacy DB 재사용 결정 → writer 중지 → SQLite consistent backup → backup integrity verify → known legacy fingerprint verify → current Operational tables additive create → migration metadata row → PRAGMA user_version = 3 → schema/integrity/regression tests → cutover

Fresh Bootstrap에서는?

빈 data/state/collector.db → StateStore가 현재 Schema 개정 3 생성 → project_state 없음 → committed_watermark 없음 → 첫 Loop A = Initial Ingest → 모든 baseline Source Commit 이후 Watermark 생성

Legacy 상태를 추정하거나 backfill하지 않기 때문에 운영 의미가 가장 단순합니다.

No Guess Backfill

Migration을 선택하더라도 Legacy 기록에서 stable project_id, committed Watermark, Source/Processing history, supersede history를 추정하지 않습니다. Fresh Bootstrap은 이 문제 자체를 피합니다.

Migration 코드/테스트는 왜 남기는가?

향후 다른 환경에서 기존 collector.db를 이어써야 할 수 있으므로 compatibility capability로 보존합니다. 단, 현재 프로젝트의 공식 Real Test는 이를 사용하지 않습니다.
