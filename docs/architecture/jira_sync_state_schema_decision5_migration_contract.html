1. Version 기준

STATE_SCHEMA_VERSION = 1 PRAGMA user_version = 1

첫 Operational State Schema를 v1로 정의합니다. 기존 user_version=0은 정식 v0로 가정하지 않고 실제 table fingerprint를 검사합니다.

상태처리
빈 DB + version 0v1 새 초기화 가능
알려진 legacy collector.db + version 0명시적 Migration 필수
version 1Schema fingerprint 검증 후 사용
version 0 + 알 수 없는 구조자동 변경 거부
지원 버전보다 높음현재 프로그램의 쓰기 거부

2. Silent Auto-Migration 금지

일반 프로그램 시작 → legacy DB 감지 → Migration required → Sync/Collector 운영 전환 중단 명시적 migration 절차 → backup → fingerprint 확인 → migration → validation → regression PASS → cutover
확정: 기존 DB는 단순히 StateStore()를 열었다는 이유만으로 자동 변경하지 않습니다.

3. Migration 전 Backup 필수

WAL 상태까지 일관되게 보존하기 위해 SQLite가 제공하는 consistent backup 방식을 우선 사용합니다. Backup 자체의 읽기/무결성 검증이 끝난 뒤에만 원본 DB를 변경합니다.

writer 중지 / migration ownership 확보 → SQLite consistent backup → backup quick_check / integrity 확인 → 원본 Migration 허용

4. 첫 Migration은 Additive

Legacy 보존

collection_runs project_runs issue_checkpoints artifacts

기존 row와 의미를 변경하거나 삭제하지 않습니다.

Operational v1 추가

sync_run project_state sync_project_run sync_issue_change

S1~S4의 새 Control Plane 상태를 추가합니다.

Migration 이력용 기술 메타 테이블은 Operational Domain Table 4개와 별도로 둘 수 있습니다.

5. Legacy 데이터로 Watermark를 추측하지 않습니다

과거 project_runs에는 stable project_id, fixed upper, Source Commit, semantic_v2 계약이 없었습니다. 따라서 마지막 수집 시간이나 마지막 Issue updated를 새 committed_watermark로 추정하여 채우지 않습니다.

Migration → legacy 기록은 보존만 → 새 project_state를 억지로 backfill하지 않음 첫 Operational Sync → 정식 Project Discovery → project_id 기반 상태 생성 → Initial Ingest로 baseline 설정 → 이후 Delta Sync

6. Idempotent + Fail-Closed

재실행

이미 v1이면 fingerprint 검증 후 no-op. 같은 Migration을 반복해도 중복 테이블/데이터를 만들지 않습니다.

모르는 DB

예상하지 못한 table/column 구조라면 수정하지 않고 실패시킵니다.

Migration Transaction 중 실패하면 Schema 변경과 user_version은 이전 상태로 rollback되어야 합니다.

7. 완료 Gate

[ ] backup 검증 PASS [ ] PRAGMA integrity / quick check PASS [ ] user_version = 1 [ ] 4개 Operational table fingerprint PASS [ ] index / constraint 확인 PASS [ ] legacy row 보존 확인 [ ] 기존 StateStore / Resume regression PASS [ ] empty DB → v1 PASS [ ] known legacy → v1 PASS [ ] v1 재실행 no-op PASS [ ] unknown schema migration 거부 PASS [ ] failure rollback PASS
모두 PASS 전에는 Operational Sync 사용 금지.

8. Rollback

첫 v1은 additive migration이므로 복잡한 역 Migration보다 검증된 pre-v1 backup 복원을 기본 복구 경로로 둡니다.

서비스/Writer 중지 → 문제 DB 별도 보존 → verified pre-v1 backup 복원 → integrity 확인 → legacy Collector / Resume 확인
