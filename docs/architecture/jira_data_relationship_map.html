0. 관계도를 보기 전에 네 줄만

① Jira Issue는 계속 변한다jira_id는 같은 업무의 장기 identity, issue_version은 내용이 바뀐 의미 상태입니다.
② Knowledge도 재생성될 수 있다Generation은 lineage, Attempt는 실제 1차/2차/3차 생성 시도입니다.
③ 검색 문장은 근거가 있어야 한다Knowledge Item은 Evidence를 통해 Comment/Description 등 실제 Source로 돌아갈 수 있어야 합니다.
④ Embedding은 위 구조를 대체하지 않는다Vector는 knowledge_item_id에 매핑되는 검색 artifact일 뿐입니다.
현재 Gate: M7 SQLite real-run PASS → M8-01 corpus PASS → M8-02 adapter 구현 완료 → M8-03 실제 BGE-M3 285 vector 검증.

1 → N왼쪽 하나에 오른쪽 여러 개가 붙을 수 있다는 뜻입니다. 예: Attempt 하나 → 여러 Knowledge Item.

Accepted pointer여러 Attempt 중 실제로 승인된 Attempt가 무엇인지 Generation이 가리킵니다.

Authoritative 구조

  • jira_id가 Issue identity, issue_key는 사람이 읽는 locator입니다.
  • Issue Version은 source_hash 기반 immutable state입니다.
  • Knowledge Generation은 Version + Contract lineage입니다.
  • Knowledge Attempt가 실제 재생성 회차이며 ka_ + attempt_no를 가집니다.
  • Knowledge Item / Review는 Attempt에 연결됩니다.
  • Evidence는 exact ref를 보존하고 Source까지 round-trip 해야 합니다.
  • M8 기본 입력은 active Generation의 accepted Attempt Knowledge입니다.

ID Ladder

jira_id → iv_ → kc_ → kg_ → ka_ → ki_ → ke_

Embedding identity는 이 Knowledge identity를 대체하지 않고 ec_ / emb_ mapping 계층으로 추가됩니다.

3. 가장 자주 헷갈리는 세 가지

Run ≠ Version파이프라인을 다시 실행했다고 Issue 내용이 바뀐 것은 아닙니다. 같은 source_hash면 같은 Version입니다.
Generation ≠ AttemptGeneration은 retry lineage, Attempt는 실제 생성 회차입니다.
History ≠ RetrievalDB는 과거를 보존하지만 기본 검색에는 active accepted Knowledge만 사용합니다.
Vector ≠ KnowledgeEmbedding은 Knowledge Item의 파생 검색 표현이며 원문/근거를 대체하지 않습니다.
