이번 레이아웃 개선 포인트

  • 화살표가 노드 박스 위를 길게 가로지르지 않도록 직교 라우팅(orthogonal routing) 적용
  • Project → Issue Hub → 상세 엔티티 → 산출물의 좌·중앙·우 계층 구조 강화
  • Edge label이 다른 박스와 겹치지 않도록 각 경로의 주요 세그먼트에 배치
  • Project Entity / Layer Pipeline / One-Issue 관점을 분리해 읽기 목적별 탐색 가능

기술적 해석 포인트

1. RAW는 사실 기준

data/raw/runs/<run_id>/... 아래의 Jira 원본 JSON은 수정하지 않습니다. 모든 파생 데이터는 이 계층으로 되돌아갈 수 있어야 합니다.

2. ANALYSIS는 검색 가능한 정규화 계층

issues.jsonl, comments.jsonl, attachments.jsonl, issue_relationships.jsonl, custom_field_*.jsonl로 의미 단위를 분리합니다.

3. Relationship는 두 층으로 해석

  • Issue Link — blocks / relates / duplicates 등
  • Hierarchy — subtasks 기반의 parent_of 관계

4. Custom Field는 Catalog + Values

220개 정의 전체는 Catalog로 보존하고, 실제 값 447개는 Values로 분리합니다. 그래야 새 프로젝트가 들어와도 DB 스키마를 흔들지 않고 흡수할 수 있습니다.

5. Knowledge Input은 Issue 중심 허브

Issue + Comments + Attachments + Relationships + Custom Field를 한 패키지로 묶어 Agent 입력 단위로 사용합니다. 이는 이후 Knowledge Extraction의 직접 입력이 됩니다.

6. 다음 단계는 Knowledge Extraction

이후에는 OpenCode Agent가 이슈 전체를 읽고 problem, context, action, decision, result, conclusion을 추출하는 구조화 지식 계층을 생성합니다.

이 문서는 학습용 구조 시각화입니다. 민감한 업무 본문은 포함하지 않고, 현재까지 검증된 구조와 산출물 연결만 시각적으로 정리했습니다.
