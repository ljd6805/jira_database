현재 authoritative 구조

  • jira_id가 Issue identity, issue_key는 locator입니다.
  • Issue Version은 source_hash 기반 immutable state입니다.
  • Knowledge Generation은 Version + Contract lineage입니다.
  • Knowledge Attempt가 1/2/3차 실제 재생성 회차이며 각각 ka_ ID를 가집니다.
  • Knowledge Item / Review는 Generation이 아니라 Attempt에 연결됩니다.
  • Evidence는 exact ref를 보존하고 Source까지 round-trip 해야 합니다.
  • Historical은 DB에 남고 기본 Retrieval에는 active accepted Attempt만 사용합니다.

ID Ladder

jira_id → iv_ → kc_ → kg_ → ka_ → ki_ → ke_

ka_ = H(kg_, attempt_no)이므로 generation 내부 재시도 회차가 유실되지 않습니다.
