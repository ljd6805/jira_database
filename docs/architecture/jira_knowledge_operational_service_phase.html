Continuous Jira Knowledge Service
2-Loop + Latest-Only

Functional MVP를 지속 운영 서비스로 확장합니다. Source 최신화와 Knowledge/Embedding/Publish를 독립 실행하고, 중간 Source Version은 보존하되 비싼 AI 처리는 최신 Version만 수행합니다.

1. 목표 아키텍처

Jira Server ↓ [Loop A · SOURCE SYNC] Project Discovery → 새 프로젝트 자동 발견 → Delta Issue Sync / Initial / Catch-up → RAW / ANALYSIS / Knowledge Input → semantic_v2 → source_hash 동일 = unchanged → source_hash 변경 = changed → Source History 모두 보존 → SOURCE_COMMITTED / Watermark / Source Ready → 이전 미완료 Work superseded ↓ latest-only durable backlog [Loop B · KNOWLEDGE PROCESSING / PUBLISH] latest + source-ready Work만 처리 → OpenCode Knowledge → latestness re-check → Review / Evidence / Knowledge DB → Embedding / FAISS staging → latestness re-check → Atomic Publish ↓ Published Corpus → Central Remote MCP → Team OpenCode
delta-first: 운영 기본은 변경분 처리이며 full rebuild는 복구/마이그레이션/검증용 경로입니다.

2. Loop A · 지속적인 Jira 업데이트

Project Discovery

접근 가능한 프로젝트를 반복 탐색하고 새 프로젝트를 자동 발견합니다. stable project_id Registry를 유지합니다.

Delta-first

Project별 Watermark + 5분 overlap + fixed upper로 Issue Delta Detection을 수행합니다.

checkpoint / resume

Source cursor와 Source Commit을 durable하게 기록해 실패 Project만 재개합니다.

Loop A는 OpenCode, Embedding, FAISS 완료를 기다리지 않습니다.

3. Loop B · Latest-Only Knowledge Processing

Source History V1 → V2 → V3 → V4 모두 보존 Knowledge Processing V2 pending → superseded V3 pending → superseded V4 latest → OpenCode / Evidence / Embedding / Publish

Running 구버전이 새 Source Version에 밀리면 호출을 강제 취소하지 않고 결과 도착 후 latestness를 재검사합니다. stale이면 Active/Embedding/Publish로 진행하지 않습니다.

6. Central Remote MCP의 책임

Remote MCP만으로 운영 서비스가 완성되는 것은 아닙니다. MCP는 Sync Engine이 아니며 Loop A/B가 유지한 마지막 정상 Published Corpus를 검색/근거 복원용으로 제공합니다.
Published Corpus → FAISS Top-K → Knowledge DB / Evidence Resolver → search_jira_knowledge / get_jira_issue → OpenCode

7. 운영 KPI

Source Lag

Project watermark 최신성.

Publish Lag

Source Head와 Published Head 차이.

Latest Backlog

실제로 처리해야 하는 최신 pending/failed Work 수와 oldest age.

Supersede Ratio

중간 Version이 얼마나 자주 최신 Version에 밀리는지.

Processing Throughput

시간당 Published 수.

OpenCode Latency / Error

낮/밤 시간대 편차와 실패율.

8. Project 비노출과 권한 정책

프로젝트 권한 상실

Project가 discovery에서 보이지 않아도 기존 Knowledge를 자동 삭제하지 않습니다. 완전한 discovery가 성공한 경우에만 unavailable로 표시합니다.

팀원별 Jira 권한

중앙 MCP가 원래 Jira의 사용자별 접근 권한을 그대로 재현해야 하는지는 아직 정책 미확정입니다. Functional MVP에서는 제외했던 항목이므로 Team Pilot 전에 별도 결정합니다.
