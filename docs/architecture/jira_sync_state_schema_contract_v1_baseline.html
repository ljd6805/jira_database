과거 Operational State 설계 · 개정 1

현재 구현 기준이 아닙니다. Source와 Publish 상태를 하나의 sync_run 안에 함께 두던 초기 설계였고, 실제 구현 전에 2-Loop 아키텍처로 대체되었습니다.

과거 핵심 구조

sync_run project_state sync_project_run sync_issue_change sync_run 안에 → discovery_status → source_status → publish_status → run_status

왜 대체됐나?

OpenCode 지연이 Jira Source 최신화까지 막지 않도록 실행 identity를 분리해야 했습니다. 이후 source_sync_run과 processing_run이 별도 실행으로 분리되었습니다.

현재 기준

Loop A source_sync_run → source_project_run → SOURCE_COMMITTED / Watermark Durable backlog sync_issue_change → Source Ready + Latest Loop B processing_run → Knowledge → Embedding → Publish

현재 2-Loop 공식 아키텍처와 현재 Operational State 설계 · 개정 3를 사용합니다.

번호 읽는 법
