SYNC CONTRACT · DECISION 6 · FINAL · 2026-08-27

Jira의 현재 상태와
축적된 Knowledge를 분리한다

Project나 Issue가 Jira에서 더 이상 보이지 않거나 삭제되더라도, 이미 축적된 업무지식의 가치가 사라지는 것은 아닙니다. Decision 6은 Source Sync 상태와 Knowledge 보존/검색 정책을 분리합니다.

FIXED · KNOWLEDGE RETENTION FIRST

1. 가장 중요한 원칙

Knowledge DB는 Jira Mirror가 아닙니다. Jira는 현재 원본 상태를 제공하고, Knowledge DB는 과거부터 축적된 업무지식을 보존합니다. 따라서 Jira에서의 삭제·비노출은 Knowledge 삭제 이벤트가 아닙니다.
Jira 현재 상태 = 지금 Source Sync가 가능한가? Knowledge DB = 지금까지 축적한 업무지식은 무엇인가? 두 질문을 분리한다.

2. Project가 안 보일 때

Project Discovery 전체 SUCCESS 기존 project_id가 이번 목록에 없음 ↓ visibility_state = unavailable ↓ 이번 Sync에서는 그 Project를 건너뜀 ↓ committed_watermark 유지 ↓ 기존 Knowledge / Embedding / FAISS 그대로 유지 ↓ Retrieval 계속 제공
확정: unavailable은 Sync 상태입니다. Retrieval 차단 상태가 아닙니다.

3. Project나 Issue가 실제로 삭제되었더라도

삭제 사실을 알게 되더라도 과거 Knowledge를 자동 삭제하거나 검색에서 제외하지 않습니다.

RAW

보존

Issue Version / Knowledge

보존

Embedding / Retrieval

기본적으로 계속 사용

이유: 해결 이력, 장애 원인, 과거 설계 판단, 운영 경험은 Jira Issue가 삭제된 뒤에도 업무지식으로 가치가 있습니다.

4. 다시 접근 가능해지면

기존 project_id가 다시 visible ↓ Initial Ingest 하지 않음 ↓ 보존한 committed_watermark 사용 ↓ lower = watermark - 5분 overlap upper = 이번 Sync 고정 상한 ↓ Catch-up Delta Sync ↓ NEW / CHANGED / UNCHANGED ↓ 필요한 변경만 downstream 갱신
확정: 같은 project_id의 재등장은 전체 재수집이 아니라 Catch-up Delta Sync입니다.

5. Reconcile은 필수 경로가 아닙니다

삭제된 Issue를 찾아내더라도 Knowledge를 제거하지 않을 것이므로, 삭제 탐지를 위해 Full Reconcile을 Sync의 필수 단계로 둘 필요가 없습니다.

기본 Sync Project Discovery → visible Project만 Delta Sync → unavailable Project는 skip 선택 기능 Reconcile → "현재 Jira에도 존재하는가?" 같은 메타데이터가 실제로 필요할 때만 추가

6. Registry와 Retrieval의 역할 분리

Project Registry

project_id, current key/name, visible/unavailable, last_seen, last_synced, watermark 등을 관리합니다.

질문: 지금 Jira Source와 동기화할 수 있는가?

Knowledge Retrieval

축적된 active Knowledge와 Evidence를 검색합니다.

질문: 지금까지 축적된 업무지식 중 무엇이 질문에 도움이 되는가?

7. Decision 6 최종 규칙

1. Project identity = project_id 2. 처음 보는 project_id = Initial Ingest 3. 기존 Project not visible = unavailable 4. unavailable Project = 이번 Sync에서 skip 5. Watermark / RAW / History / Knowledge / Vector = 보존 6. Retrieval = 그대로 유지 7. Project/Issue 삭제 = Knowledge 자동 삭제 아님 8. 같은 project_id 재등장 = Watermark 기반 Catch-up Delta 9. Reconcile = 선택 기능, 필수 Sync 경로 아님 10. Retrieval 차단이 필요하면 Jira visibility와 별도의 명시적 정책으로만 수행
