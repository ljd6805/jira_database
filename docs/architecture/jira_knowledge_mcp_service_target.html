Remote MCP는 최종 서비스의
중앙 조회 경계입니다.

M11의 local stdio는 MVP 호환성 검증용이었습니다. 실제 팀 서비스에서는 중앙 서버가 Jira Knowledge DB, FAISS, BGE-M3 설정을 소유하고 팀원 OpenCode는 Remote MCP URL에 접속합니다. 다만 Remote MCP만으로 서비스가 완성되는 것은 아니며, 지속 Jira 동기화와 증분 Knowledge/Index 갱신이 함께 동작해야 합니다.

REMOTE MCP = OPERATIONAL SERVICE COMPONENT · NOT THE WHOLE SERVICE

1. 전체 운영 서비스 안에서의 위치

Jira ↓ 지속 Project Discovery / Delta Sync RAW / Issue Version ↓ Knowledge / Evidence ↓ Embedding / FAISS Delta Update ↓ Central Remote MCP ← 이 문서의 범위 ↓ 팀원 OpenCode

운영 서비스 전체 범위는 MVP 이후 운영 서비스 단계 문서를 기준으로 합니다.

2. 최종 Remote MCP 구조

팀원 A · OpenCode ─┐ 팀원 B · OpenCode ─┼──── Remote MCP / HTTPS ────┐ 팀원 C · OpenCode ─┘ │ ▼ ┌────────────────────────┐ │ jira-knowledge MCP │ │ 중앙 서버 │ ├────────────────────────┤ │ search_jira_knowledge │ │ get_jira_issue │ └──────────┬─────────────┘ │ ┌──────────────────────────┼──────────────────────────┐ ▼ ▼ ▼ SQLite DB FAISS Index BGE-M3 API

3. 팀원 PC와 서버 책임

팀원 OpenCode중앙 서비스
Remote MCP URL 설정Jira 지속 동기화 파이프라인 실행
필요한 인증 정보SQLite / FAISS 최신 Active 상태 유지
Tool 호출 / Agent 답변BGE-M3 endpoint/secret 관리

jira_database clone 불필요서비스 버전/로그/health 관리

4. Transport 방향

1순위 · Streamable HTTP

OpenCode 1.18.12 Remote MCP client가 먼저 시도하고 MCP Python SDK 2.1.1도 서버 transport로 지원합니다.

Fallback · SSE

OpenCode 1.18.12가 Streamable HTTP 실패 시 시도하는 호환 경로입니다.

5. 서버 설정

중앙 서버 .env JIRA_KNOWLEDGE_DB_PATH=... JIRA_RETRIEVAL_ARTIFACT_DIR=... BGE_M3_ENDPOINT=... BGE_M3_API_KEY=... optional BGE_M3_HEADERS_JSON=... optional

실제 값은 저장소에 커밋하지 않습니다.

6. OpenCode 측 목표 설정

{ "mcp": { "jira-knowledge": { "type": "remote", "url": "https://.../mcp", "timeout": 30000 } } }

실제 사내 URL/token/header는 공개 문서에 기록하지 않습니다.

7. 아직 Freeze하지 않은 것

인증/접근 제어

Bearer, OAuth, 사내 Proxy와 팀원별 Jira 권한 정책을 운영 설계에서 결정합니다.

배포 방식

systemd, Docker 등은 서버 환경과 운영 방식 확인 후 결정합니다.

운영 규모

동시 사용자/QPS/timeout/cache는 팀 Pilot 측정 후 결정합니다.
