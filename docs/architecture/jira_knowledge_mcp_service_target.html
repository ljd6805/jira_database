MCP SERVICE TARGET · 2026-08-28

Central MCP는 두 Loop를 실행하지 않습니다.

MCP는 마지막 정상 Published Corpus를 읽어 Knowledge와 Evidence를 제공하는 상시 Retrieval Service입니다.

현재 위치

Loop A · Source Sync → Jira 최신 Source / backlog 생산 Loop B · Knowledge Processing / Publish → backlog 소비 / 새 Published Corpus 생성 Central MCP → Published Corpus만 읽음 → search_jira_knowledge → get_jira_issue → Team OpenCode

MCP 책임

자연어 질문을 Embedding하고 FAISS에서 Top-K Knowledge를 찾고, Knowledge DB를 통해 Evidence를 복원하며, Tool 결과로 반환합니다. 생성형 최종 답변은 OpenCode가 작성합니다.

MCP가 하지 않는 것

Jira Project Discovery, Delta Sync, Watermark 이동, backlog claim, OpenCode Knowledge Generation, Embedding 생성, Publish orchestration을 하지 않습니다.

새 Publish 실패 시

Source Head V5 Loop B V5 Publish 실패 Published Head V4 MCP → V4 last-known-good 계속 서비스

따라서 MCP 가용성과 Knowledge 최신성은 별개의 운영 지표입니다.

운영 연동 지표

MCP 자체 health와 함께 외부에서 Source Lag, Publish Lag, Backlog Depth를 보여줄 수 있지만, 이 지표를 계산하기 위해 MCP가 Sync Engine이 될 필요는 없습니다.
