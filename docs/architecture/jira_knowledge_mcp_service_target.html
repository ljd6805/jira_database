MCP SERVICE TARGET · 2026-08-31

Central MCP는 운영 서비스의 조회 경계입니다.

Remote MCP만으로 서비스가 완성되는 것은 아닙니다. Loop A와 Loop B가 최신 Source와 Published Corpus를 유지하고, MCP는 마지막 정상 Published Corpus를 읽어 Knowledge와 Evidence를 제공합니다.

현재 위치

Loop A · Source Sync → Jira 최신 Source / latest-only backlog 생산 Loop B · Knowledge Processing / Publish → 최신 Work 소비 / 새 Published Corpus 생성 Central MCP → Published Corpus만 읽음 → search_jira_knowledge → get_jira_issue → Team OpenCode

MCP 책임

자연어 질문을 Embedding하고 FAISS에서 Top-K Knowledge를 찾고, Knowledge DB를 통해 Evidence를 복원하며 Tool 결과로 반환합니다. 생성형 최종 답변은 OpenCode가 작성합니다.

MCP가 하지 않는 것

Jira Project Discovery, Delta Issue Sync, Watermark 이동, supersede 판단, backlog claim, OpenCode Knowledge Generation, Embedding 생성, Publish orchestration을 하지 않습니다.

새 Publish 실패 시

Source Head = 최신 Loop B Publish 실패 Published Head = 이전 정상 Version MCP → last-known-good Published Corpus 계속 서비스

따라서 MCP 가용성과 Knowledge 최신성은 별개의 운영 지표입니다.

운영 연동 지표

MCP 자체 health와 함께 Source Lag, Publish Lag, Latest Backlog, supersede ratio를 외부 운영 화면에서 보여줄 수 있습니다. MCP가 직접 Sync Engine이 될 필요는 없습니다.
