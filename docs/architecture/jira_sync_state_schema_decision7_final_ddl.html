1. S7의 원칙

DB가 직접 막아야 하는 것

PK/FK, enum, 음수 count, cursor pair 불일치, 동일 semantic Work Item 중복, 잘못된 stage dependency처럼 데이터 자체가 모순되는 상태.

Application Transaction이 막아야 하는 것

source_committed + Watermark 동시 commit, 실제 Retrieval publish 후 State published 기록, Knowledge DB logical ID 존재 확인처럼 여러 저장소/행을 아우르는 운영 불변식.

핵심: SQLite CHECK로 억지로 모든 업무 흐름을 구현하지 않습니다. DDL은 구조적 모순을 차단하고, S4 Transaction Contract는 StateStore repository method와 테스트로 강제합니다.

2. 전체 Schema 구성

Legacy MVP Tables · 그대로 보존 collection_runs project_runs issue_checkpoints artifacts Operational Domain Tables · 4개 sync_run project_state sync_project_run sync_issue_change Technical Metadata · 1개 state_schema_migration PRAGMA user_version = 1

state_schema_migration은 S2의 4개 Domain Table에 포함되지 않는 Migration 감사용 기술 메타데이터입니다.

4. sync_run DDL

CREATE TABLE IF NOT EXISTS sync_run (
    sync_run_id TEXT PRIMARY KEY
        CHECK(length(sync_run_id) = 35 AND substr(sync_run_id, 1, 3) = 'sr_'),
    started_at TEXT NOT NULL,
    finished_at TEXT,
    upper_bound TEXT NOT NULL,
    discovery_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(discovery_status IN ('pending','running','completed','failed')),
    source_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(source_status IN ('pending','running','completed','partial','failed')),
    publish_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(publish_status IN ('pending','running','completed','partial','failed','not_required')),
    run_status TEXT NOT NULL DEFAULT 'running'
        CHECK(run_status IN ('running','completed','partial','failed')),
    error_summary TEXT,
    CHECK(
        (run_status = 'running' AND finished_at IS NULL)
        OR
        (run_status IN ('completed','partial','failed') AND finished_at IS NOT NULL)
    )
);
ID 형식: sr_ + UUID4 full hex = 35자. 시간 정렬은 ID가 아니라 started_at로 수행합니다.

5. project_state DDL

CREATE TABLE IF NOT EXISTS project_state (
    project_id TEXT PRIMARY KEY,
    current_key TEXT NOT NULL CHECK(length(current_key) > 0),

        (visibility_state = 'unavailable' AND unavailable_since IS NOT NULL)

         AND last_source_success_run_id IS NULL

current_key는 Index는 만들지만 UNIQUE는 걸지 않습니다. authoritative identity는 오직 project_id입니다.

6. sync_project_run DDL

CREATE TABLE IF NOT EXISTS sync_project_run (
    sync_run_id TEXT NOT NULL REFERENCES sync_run(sync_run_id),
    project_id TEXT NOT NULL REFERENCES project_state(project_id),
    operation_kind TEXT NOT NULL
        CHECK(operation_kind IN ('initial_ingest','delta','catchup','skip_unavailable')),
    lower_bound TEXT,
    upper_bound TEXT NOT NULL,
    source_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(source_status IN (
            'pending','running','source_committed','partial','failed','skipped_unavailable'
        )),
    started_at TEXT,
    finished_at TEXT,
    candidate_count INTEGER NOT NULL DEFAULT 0 CHECK(candidate_count >= 0),
    new_count INTEGER NOT NULL DEFAULT 0 CHECK(new_count >= 0),
    changed_count INTEGER NOT NULL DEFAULT 0 CHECK(changed_count >= 0),
    unchanged_count INTEGER NOT NULL DEFAULT 0 CHECK(unchanged_count >= 0),
    cursor_updated_at TEXT,
    cursor_jira_id TEXT,
    error_message TEXT,
    PRIMARY KEY(sync_run_id, project_id),
    CHECK(
        (cursor_updated_at IS NULL AND cursor_jira_id IS NULL)
        OR
        (cursor_updated_at IS NOT NULL AND cursor_jira_id IS NOT NULL)
    ),
    CHECK(new_count + changed_count + unchanged_count <= candidate_count),
    CHECK(
        source_status != 'source_committed'
        OR new_count + changed_count + unchanged_count = candidate_count
    ),
    CHECK(
        (operation_kind IN ('delta','catchup') AND lower_bound IS NOT NULL)
        OR
        (operation_kind IN ('initial_ingest','skip_unavailable') AND lower_bound IS NULL)
    ),
    CHECK(
        (operation_kind = 'skip_unavailable' AND source_status = 'skipped_unavailable')
        OR
        (operation_kind != 'skip_unavailable' AND source_status != 'skipped_unavailable')
    ),
    CHECK(
        (source_status IN ('pending','running') AND finished_at IS NULL)
        OR
        (source_status IN ('source_committed','partial','failed','skipped_unavailable')
         AND finished_at IS NOT NULL)
    )
);
S4와 연결: DDL 자체는 Watermark를 자동 갱신하지 않습니다. source_status='source_committed' 갱신과 project_state.committed_watermark=upper_bound는 반드시 같은 StateStore Transaction method에서 실행합니다.

7. sync_issue_change DDL

CREATE TABLE IF NOT EXISTS sync_issue_change (
    work_item_id TEXT PRIMARY KEY
        CHECK(length(work_item_id) = 67 AND substr(work_item_id, 1, 3) = 'sw_'),
    project_id TEXT NOT NULL REFERENCES project_state(project_id),
    jira_id TEXT NOT NULL,
    observed_issue_key TEXT NOT NULL,
    jira_updated_at TEXT,
    source_hash TEXT NOT NULL CHECK(length(source_hash) > 0),
    source_hash_profile TEXT NOT NULL
        CHECK(source_hash_profile = 'semantic_v2'),
    change_kind TEXT NOT NULL CHECK(change_kind IN ('new','changed')),
    discovered_run_id TEXT NOT NULL REFERENCES sync_run(sync_run_id),
    last_attempt_run_id TEXT REFERENCES sync_run(sync_run_id),
    source_committed_at TEXT NOT NULL,
    issue_version_id TEXT,
    knowledge_generation_id TEXT,
    knowledge_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(knowledge_status IN ('pending','running','completed','failed')),
    embedding_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(embedding_status IN ('pending','running','completed','failed')),
    publish_status TEXT NOT NULL DEFAULT 'pending'
        CHECK(publish_status IN ('pending','running','published','failed')),
    error_stage TEXT CHECK(error_stage IS NULL OR error_stage IN ('knowledge','embedding','publish')),
    error_message TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    published_at TEXT,
    UNIQUE(jira_id, source_hash, source_hash_profile),
    CHECK(embedding_status = 'pending' OR knowledge_status = 'completed'),
    CHECK(publish_status = 'pending' OR embedding_status = 'completed'),
    CHECK(
        (publish_status = 'published' AND published_at IS NOT NULL)
        OR
        (publish_status != 'published' AND published_at IS NULL)
    ),
    CHECK(
        error_stage IS NULL
        OR (error_stage = 'knowledge' AND knowledge_status = 'failed')
        OR (error_stage = 'embedding' AND embedding_status = 'failed')
        OR (error_stage = 'publish' AND publish_status = 'failed')
    )
);

DB가 막는 것

Knowledge가 완료되지 않았는데 Embedding이 진행되는 상태, Embedding이 완료되지 않았는데 Publish가 진행되는 상태, 같은 semantic state Work Item 중복.

Application이 확인하는 것

issue_version_id, knowledge_generation_id가 실제 Knowledge DB에 존재하는지와 실제 Retrieval active pointer가 무엇인지.

8. 과거 semantic state가 다시 현재가 되는 경우

예: 같은 Issue의 Source가 A → B → 다시 A로 돌아올 수 있습니다. A의 Work Item은 deterministic identity 때문에 이미 존재합니다.

과거 A Work Item → Knowledge/Embedding 완료 → Published 현재 B가 active Published Jira Source가 다시 A로 변경 ↓ A Work Item 새 row 생성 X A의 Knowledge / Embedding 재사용 ↓ Source Head A != 현재 Published Head B ↓ A Work Item의 Publish stage를 재개/재활성화 ↓ Atomic Publish → Published Head A
D7 원칙 유지: Work Item의 과거 published 이력만 보고 “서비스가 최신”이라고 판단하지 않습니다. 현재 Source Head와 실제 Published Head의 일치 여부가 최종 기준입니다. 재활성화 시 기존 Knowledge/Embedding은 재사용하고 Publish만 다시 수행할 수 있습니다.

11. Schema v1 초기화 / Migration 순서

PRAGMA foreign_keys = ON PRAGMA journal_mode = WAL legacy fingerprint / backup / migration ownership ↓ BEGIN IMMEDIATE → state_schema_migration + 4 domain tables + indexes 생성 → schema fingerprint 검증 → migration history 기록 → PRAGMA user_version = 1 COMMIT ↓ post-migration integrity + regression Gate ↓ Operational Sync 허용
주의: Migration의 실제 SQLite pragma/transaction 세부 순서는 구현 테스트에서 검증합니다. S5의 “backup first / fail-closed / validation before cutover”가 우선 계약입니다.
