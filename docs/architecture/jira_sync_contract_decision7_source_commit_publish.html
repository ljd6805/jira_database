SYNC CONTRACT · DECISION 7 · 2026-08-27

Source Commit과 Publish는
같은 완료가 아닙니다.

Jira 최신 원본을 안전하게 확보한 시점과, 그 변경분이 Knowledge·Embedding·FAISS까지 반영되어 사용자 검색에 쓰이는 시점을 분리합니다.

D1~D6 FIXED · D7 REVIEWING · NO IMPLEMENTATION YET
30초 요약

1. 창고 입고와 매대 진열로 생각하면 쉽습니다

Source Commit = 입고 완료

Jira에서 최신 Issue/Comment 등을 가져와 source_hash를 계산하고 NEW/CHANGED/UNCHANGED 판정까지 안전하게 기록한 상태입니다.

Publish = 진열 완료

새 Knowledge가 검증되고 Embedding과 Retrieval까지 준비되어 실제 검색 결과에 새 버전이 사용되는 상태입니다.

핵심: 입고가 끝났다고 기존 매대 상품을 바로 치우지 않습니다. 새 상품이 완전히 준비될 때까지 기존 Published Knowledge를 계속 제공합니다.

2. Source Commit은 정확히 어디까지인가?

Jira Delta Candidate ↓ Issue / Comment / Relationship / Custom Field 수집 ↓ RAW / ANALYSIS 안전 저장 ↓ source_hash semantic_v2 계산 ↓ NEW / CHANGED / UNCHANGED 판정 ↓ 변경 Work Item durable 저장 ↓ SOURCE_COMMITTED

여기까지 끝나면 “Jira 최신 사실을 놓치지 않고 확보했다”고 말할 수 있습니다. 하지만 아직 사용자가 새 Knowledge를 검색할 수 있다는 뜻은 아닙니다.

3. Source Commit이 끝나면 Watermark는 이동해도 됩니다

Decision 5에서 downstream 상태를 별도로 기억하기로 했기 때문에, Jira Source를 다시 읽기 위해 Watermark를 붙잡아둘 필요가 없습니다.

Project A window lower = 10:25 upper = 10:40 후보 Issue 3개 ABC-1 source committed ✓ ABC-2 source committed ✓ ABC-3 source committed ✓ ↓ Project source window complete ↓ committed_watermark = 10:40 이후 Knowledge / Embedding / Publish는 별도 checkpoint로 계속
추천: 해당 Project의 window 안 모든 후보 Source가 안전하게 commit되면 Watermark를 upper까지 전진시킵니다. Downstream 실패는 Watermark를 되돌리지 않습니다.

4. 단, Source 후보 하나라도 실패하면?

ABC-1 source committed ✓ ABC-2 source failed ✗ ABC-3 source committed ✓ → Project window SOURCE_COMMITTED 아님 → Project Watermark 이동 X → 같은 Run Resume 우선 → ABC-2부터 재개

개별 Issue의 성공 결과는 보존하지만, Project의 이번 시간 구간을 “모두 읽었다”고 선언할 수 없으므로 Project Watermark는 그대로 둡니다.

5. Publish는 어디까지 끝나야 하나?

CHANGED source version ↓ Knowledge Generation = candidate ↓ Attempt / Review PASS ↓ Evidence resolve 가능 ↓ Embedding 생성 / 검증 ↓ FAISS / Retrieval mapping 반영 준비 ↓ 새 Retrieval view 전환 ↓ PUBLISHED
Publish의 의미: “새 지식이 존재한다”가 아니라 새 지식과 검색 인덱스가 서로 일치한 상태로 실제 사용자에게 제공된다는 뜻입니다.

6. Publish 전에는 기존 Knowledge를 계속 제공합니다

현재 Version V1 Generation G1 = active Retrieval = G1 Jira 변경 발견 Version V2 source committed Generation G2 = candidate G2 Knowledge 생성 실패 또는 Embedding 미완료 ↓ Retrieval은 여전히 G1 G2 전체 준비 완료 ↓ G1 historical G2 active Retrieval → G2

이 패턴은 이미 M6에서 정한 candidate → active 원칙과 같습니다. 새 Generation이 PASS하기 전에는 기존 active를 유지합니다.

7. 두 개의 Head를 기억하면 상태가 명확합니다

Source Head

Jira에서 가장 최근 안전하게 commit한 Version.

source_head = V2

Published Head

현재 Retrieval이 실제로 사용 중인 Version.

published_head = V1
source_head == published_head → 최신 Source가 검색에 반영됨 source_head != published_head → Source는 더 최신 → Publish 작업이 아직 남아 있음
장점: “Jira는 최신인데 검색은 아직 이전 버전”인 상태를 숨기지 않고 정확히 표현할 수 있습니다.

8. 실패 위치별 재개

실패 지점이미 보존된 것다음 재개
Source 수집 실패완료된 Issue Source실패 Source부터

9. Half-Publish는 허용하지 않습니다

SQLite는 새 G2를 active라고 말하는데 FAISS는 아직 G1 vector를 보고 있으면 검색 결과가 꼬입니다.

피해야 할 상태

DB active = G2 Embedding = G2 FAISS mapping = G1 → 서로 불일치

원하는 상태

새 Knowledge / Embedding / Index 모두 staging에서 준비 ↓ 검증 PASS ↓ Retrieval이 보는 active pointer 전환
구현 방식은 나중에 결정: atomic file replace, manifest pointer, DB publish pointer 등 여러 방법이 가능합니다. 지금 계약에서는 사용자에게 반쯤 갱신된 상태를 노출하지 않는다만 고정합니다.

10. Project나 Issue가 Jira에서 사라져도 이 규칙은 변하지 않습니다

Decision 6에서 정했듯 Jira Source lifecycle과 Knowledge lifecycle은 별개입니다.

Jira에서 Project / Issue 삭제 또는 not visible ↓ Source Sync는 더 진행하지 못할 수 있음 ↓ 이미 PUBLISHED된 Knowledge → 그대로 보존 → 그대로 Retrieval 제공

Source가 더 이상 존재하지 않는다고 기존 Published Knowledge를 자동 unpublish하지 않습니다.

11. 상태 이름은 단순하게

source_state

pending / running / committed / failed

publish_state

pending / running / published / failed

현재성

source_head == published_head 여부로 판단

구체적인 DB 테이블/컬럼은 Sync State Schema 단계에서 Freeze합니다.

12. Decision 7 추천 결론

PROPOSED

Source Commit과 Publish를 명확히 분리한다.

SOURCE_COMMITTED = Jira Source 안전 저장 = semantic hash / 변경 판정 durable = downstream Work Item 생성 = Project window 전체 성공 시 Watermark advance 가능 PUBLISHED = 승인 Knowledge 준비 = Evidence resolve 가능 = Embedding 준비 = Retrieval index/mapping 일치 = 새 Published Head 전환 완료 Publish 전 → 기존 Published Knowledge 계속 제공 Publish 실패 → Source 재수집 없이 실패 Stage부터 Resume Half-Publish → 허용하지 않음
