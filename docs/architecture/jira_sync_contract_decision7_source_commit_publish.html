SYNC CONTRACT · DECISION 7 · FINAL · 2026-08-27

Source Commit과 Publish는
같은 완료가 아닙니다.

Jira 최신 원본을 안전하게 확보한 시점과, 그 변경분이 Knowledge·Embedding·FAISS까지 반영되어 실제 검색에 쓰이는 시점을 분리합니다.

FIXED · SOURCE COMMIT ≠ PUBLISH

1. Source Commit

Jira Source 안전 저장 → semantic_v2 source_hash 계산 → NEW / CHANGED / UNCHANGED 판정 → downstream Work Item durable 저장 → SOURCE_COMMITTED

Project의 책임 Source window가 모두 안전하게 끝나면 Watermark를 upper까지 전진할 수 있습니다.

2. Publish

승인 Knowledge → Evidence resolve → Embedding → FAISS / Mapping 일치 → 실제 Retrieval 전환 → PUBLISHED

새 Knowledge가 존재하기만 하는 것으로는 Publish가 아닙니다. 사용자 검색이 새 상태를 일관되게 사용해야 합니다.

3. 기존 Published Knowledge 보호

새 Publish 준비 중

기존 Published Knowledge를 계속 제공합니다.

Publish 실패

Source부터 재수집하지 않고 실패 Stage부터 Resume합니다.

현재 Published = V1 새 Source V2 = SOURCE_COMMITTED V2 Knowledge / Embedding 준비 중 → 검색은 V1 유지 V2 전체 준비 완료 → Published Head를 V2로 전환 → V1은 History 보존

4. Half-Publish 금지

확정: DB는 V2인데 FAISS는 V1인 식의 반쪽 상태를 사용자에게 노출하지 않습니다. 새 Published 상태가 완전히 준비된 뒤 한 번에 Retrieval 관점을 전환합니다.

5. Decision 7 최종 규칙

1. SOURCE_COMMITTED와 PUBLISHED를 분리 2. Source window 전체 성공 후 Watermark advance 가능 3. Publish 전에는 기존 Published Knowledge 계속 제공 4. Publish 실패 시 실패 Stage부터 Resume 5. Source 재수집은 필요 없음 6. Half-Publish는 허용하지 않음 7. Jira 삭제/비노출은 기존 Published Knowledge 자동 해제 이벤트가 아님
