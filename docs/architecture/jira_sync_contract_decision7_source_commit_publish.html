D7 · FIXED · 2-LOOP BOUNDARY

SOURCE_COMMITTED와 PUBLISHED는 다른 완료 경계입니다.

D9 2-Loop 채택으로 D7은 더 명확해졌습니다. Source Commit은 Loop A의 종료 경계이고 Publish는 Loop B의 종료 경계입니다.

Loop A · SOURCE_COMMITTED

Jira Source 확보 → RAW / ANALYSIS / Knowledge Input durable → semantic_v2 hash → NEW / CHANGED / UNCHANGED 판정 → NEW/CHANGED sync_issue_change durable → Project Source window 전체 완료 → source_committed + Watermark same transaction

Loop B · PUBLISHED

pending Work Item → OpenCode Knowledge → Review / Evidence → Knowledge DB → BGE-M3 Embedding → FAISS staging / mapping → 검증 → actual Retrieval atomic switch → State publish_status = published

두 Loop 사이에서 허용되는 상태

Source Head = V2 Published Head = V1 Loop A completed 가능 Loop B backlog pending 가능 사용자 Retrieval = V1 유지 V2 actual Publish 후 Published Head = V2

이 상태는 오류가 아니라 eventual consistency 구간입니다. 운영자는 Source Lag / Publish Lag / Backlog로 관찰합니다.

Half-Publish 금지

Knowledge DB, Embedding, FAISS/Mapping이 서로 다른 세대를 사용자에게 노출하지 않습니다. State의 published 표시는 실제 Retrieval 전환보다 먼저 기록할 수 없습니다.
