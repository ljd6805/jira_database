5. 현재 S5 · Migration Contract

REVIEWING

기존 DB를 보존하면서 첫 Versioned Operational Schema로 전환

STATE_SCHEMA_VERSION = 1 legacy user_version 0 → empty / known legacy / unknown fingerprint 구분 known legacy → explicit migration only → consistent backup → additive domain tables + migration metadata → user_version = 1 → integrity/schema/legacy regression tests → PASS 후 operational cutover

과거 project_runs에서 stable project_id나 committed Watermark를 추정하지 않고, 첫 Operational Sync부터 정식 상태를 구축하는 방향입니다.

6. Migration에서 절대 하지 않을 것

Silent Auto-Migration

기존 DB를 열었다는 이유만으로 정상 startup에서 몰래 변경하지 않습니다.

Guess Backfill

Legacy 수집 기록만 보고 Project Registry/Watermark를 추정하지 않습니다.

Legacy Table 파괴

첫 Migration에서 기존 table을 삭제/rename/의미 변경하지 않습니다.

검증 없는 Cutover

Backup/integrity/schema/regression Gate를 통과하지 않으면 새 Sync를 시작하지 않습니다.

7. 아직 구현하지 않습니다

현재는 Schema Contract를 만드는 단계입니다. S5와 후속 final DDL/ID 결정을 끝내고 Schema를 Freeze한 뒤 migration 코드와 StateStore 구현을 시작합니다.
