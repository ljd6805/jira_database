1. 결정 진행 상태

S1 Storage Location FIXED → existing data/state/collector.db 확장 → explicit versioned Migration REQUIRED S2 Entity Layout FIXED → 4 physical tables S3 Columns / Status FIXED → required columns / enums → stable Source resume cursor S4 Transaction Boundary REVIEWING → Watermark atomicity → crash-safe commit order S5 Migration Specification NEXT → version / backup / verify / rollback Gate 그 다음 → Schema Contract FROZEN → implementation

2. 확정된 저장 책임

Control Plane · collector.db

Sync Run, Project 현재 상태, Watermark, Resume cursor, downstream checkpoint, retry/error를 저장합니다.

Data Plane · Knowledge DB

Issue Version, Generation, Attempt, Knowledge Item, Evidence, Review 등 실제 업무지식과 족보를 보존합니다.

S1: 기존 State DB를 그대로 무변경 사용하는 것이 아니라 명시적 Schema Migration으로 운영 상태를 추가합니다.

3. 확정된 4개 물리 테이블

sync_run

한 번의 전체 Sync 범위, fixed upper, 집계 상태.

project_state

Project identity, visibility, committed Watermark.

sync_project_run

Run × Project lower/upper, Source 결과, Resume cursor.

sync_issue_change

NEW/CHANGED Work Item의 Knowledge→Embedding→Publish 상태.

4. 핵심 관계

sync_run 1 ───── N sync_project_run N ───── 1 project_state │ │ Source에서 NEW / CHANGED ↓ sync_issue_change │ ├─ issue_version_id ──→ Knowledge DB └─ knowledge_generation_id ──→ Knowledge DB project_state → Project당 현재 상태 1행 sync_run / sync_project_run → 실행 History sync_issue_change → Run을 넘어 Resume 가능한 변경 Work Item

5. S3 확정 필드의 핵심

테이블특히 중요한 필드
sync_runsync_run_id, upper_bound, discovery/source/publish/run status
project_stateproject_id, key/name, visibility, committed_watermark, last source success
sync_project_runoperation kind, exact lower/upper, counts, cursor_updated_at + cursor_jira_id, source status
sync_issue_changejira_id + source_hash + profile, discovered/last-attempt run, Knowledge/Embedding/Publish statuses
UNCHANGED: downstream Work Item을 만들지 않습니다. Project count + stable Source cursor로 같은 Run Resume를 지원합니다.

6. 현재 S4 · Transaction Boundary

REVIEWING

Watermark는 Source Commit과 같은 transaction에서만 전진

Per candidate 실제 Source 파일 durable → classification → State transaction: count + Work Item + cursor Project 전체 Source 완료 → State transaction: sync_project_run.source_status = source_committed project_state.committed_watermark = upper last source success 갱신 → COMMIT

Downstream은 각 실제 산출물을 먼저 durable하게 만든 뒤 State status를 완료로 기록하고, Publish는 실제 Retrieval 전환 후 State를 published로 기록하는 방향을 검토합니다.

7. Migration은 마지막 구현 작업이 아니라 Schema의 일부

S1에서 Migration을 필수로 확정했습니다. 따라서 S5에서 Migration version, backup, pre/post validation, idempotency, rollback/recovery Gate까지 설계한 뒤에야 Schema를 Freeze합니다.

8. 아직 구현하지 않습니다

현재는 Schema Contract를 만드는 단계입니다. 새 테이블 DDL, StateStore 코드, Delta Collector 구현은 S4/S5와 최종 Schema Freeze 이후에 시작합니다.
