D1 · Project별 committed Watermark

FIXED

각 Project는 독립적인 committed_watermark를 가집니다. 해당 Project의 Source window 전체가 안전하게 Source Commit된 경우에만 Watermark를 전진합니다.

Project A success → watermark advance Project B failure → watermark keep Project C success → watermark advance

D2 · 5분 Overlap + fixed upper + stable order

FIXED
lower = committed_watermark - 5 minutes upper = source_sync_run 시작 시 고정 updated >= lower updated < upper ORDER BY updated ASC, id ASC

경계 누락보다 안전한 중복을 선택합니다. Source Run Resume은 같은 lower/upper를 재사용합니다.

D3 · NEW / CHANGED / UNCHANGED

FIXED
판정조건처리
NEWjira_id 미존재새 semantic Work Item 생성
CHANGED같은 jira_id + 다른 source_hash새 semantic Work Item 생성
UNCHANGED같은 jira_id + 같은 source_hash기존 Version/Knowledge/Embedding 재사용, 새 Work Item 없음

Jira updated는 후보 탐색 신호일 뿐 실제 semantic identity가 아닙니다.

D4 · source_hash semantic_v2

FIXED

Knowledge 의미에 영향을 주는 Issue/Comment/Attachment/Relationship/Custom Field 값은 포함하고, 위치성 metadata와 issue.updated_at, comment.updated_at는 제외합니다.

source_hash_profile = semantic_v2

updated_at은 Delta 탐색에는 계속 사용하지만 semantic hash에는 넣지 않습니다.

D5 · Checkpoint / Resume

FIXED

Loop A Checkpoint

Project lower/upper, candidate count, stable cursor, Source Commit, Watermark를 durable하게 기록합니다.

Loop B Checkpoint

Work Item별 Knowledge / Embedding / Publish 상태를 독립적으로 기록합니다.

2-Loop 효과: Loop B가 느리거나 실패해도 Loop A Resume/다음 Source Sync를 막지 않습니다. 반대로 Jira 장애 중에도 이미 쌓인 Loop B backlog는 계속 처리할 수 있습니다.

D7 · SOURCE_COMMITTED ≠ PUBLISHED

FIXED · TWO-LOOP BOUNDARY

SOURCE_COMMITTED · Loop A

Source 산출물, semantic hash, change classification, durable Work Item이 안전하게 기록된 상태. Project 전체 Source 책임 완료 시 Watermark 전진.

PUBLISHED · Loop B

Knowledge/Review/Evidence, Embedding, FAISS/Mapping이 일치하고 실제 Retrieval active 전환까지 끝난 상태.

Source Head V2 Published Head V1 Loop A는 완료 가능 Loop B는 V2 처리 pending 사용자는 V1 계속 검색 V2 actual Publish 성공 → Published Head V2

Half-Publish는 금지하며 새 결과가 준비되기 전 기존 Published Knowledge를 제거하지 않습니다.

D8 · Run 상태는 Loop-local

REVISED BY D9

2026-08-27의 v1 D8은 하나의 Sync Run이 Source와 Publish를 함께 집계했습니다. 2-Loop 채택으로 이 집계 의미는 폐기합니다.

Runcompletedpartialfailed
source_sync_runDiscovery 신뢰 + 모든 visible Project Source 책임 완료일부 durable Source progress + 일부 실패/미완료Discovery 불신뢰 또는 필요한 Source progress 0
processing_run선택한 Work Item이 모두 terminal 상태에 도달하거나 처리할 Work 0일부 durable processing progress + 일부 실패/미완료의미 있는 processing progress 없이 실행 실패

unavailable Project는 Source Run 실패로 세지 않습니다. 어떤 Run이 실패해도 기존 Published Retrieval이 자동 중단되는 것은 아닙니다.
