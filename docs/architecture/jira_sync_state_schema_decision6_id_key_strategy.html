S6 · CURRENT ID / KEY STRATEGY

실행 Identity는 Source와 Processing으로 분리합니다.

ID 규칙 자체는 Latest-Only 정책 이후에도 유지됩니다.

ID 네 종류

종류현재 규칙
외부 IdentityJira project_id, jira_id 그대로
Source 실행 Identitysource_run_id = sr_ + UUID4.hex
Processing 실행 Identityprocessing_run_id = pr_ + UUID4.hex
Semantic Work Identitywork_item_id = sw_ + deterministic full SHA-256

Work Item identity

기술 ID 규칙 버전 STATE_ID_SCHEMA_VERSION = 2 identity material = { jira_id, source_hash, source_hash_profile } → canonical JSON → SHA-256 → sw_<64hex>

STATE_ID_SCHEMA_VERSION = 2는 Work Item ID 생성 알고리즘의 기술 버전입니다. Operational State Schema 개정 3과 같은 번호 체계가 아닙니다.

PK / FK

source_sync_run PK → source_run_id processing_run PK → processing_run_id project_state PK → project_id source_project_run PK → (source_run_id, project_id) sync_issue_change PK → work_item_id UNIQUE(jira_id, source_hash, source_hash_profile)

Work Item Run references

first_discovered_source_run_id → source_sync_run last_observed_source_run_id → source_sync_run last_source_committed_run_id → source_sync_run last_processing_run_id → processing_run

Knowledge DB의 issue_version_id/knowledge_generation_id는 cross-database logical reference이며 같은 SQLite DB 안의 FK가 아닙니다.

Latest-Only와 ID의 관계

더 최신 Source 상태가 들어와도 과거 Work Item ID를 지우거나 바꾸지 않습니다. 새 Work가 기존 미완료 Work를 superseded_by_work_item_id로 가리킬 뿐입니다.
