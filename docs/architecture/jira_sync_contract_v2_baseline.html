과거 Sync Contract · 개정 2

과거 보관본 · 현재 구현 기준 아님 · NEVER DEPLOYED

2-Loop + Source Ready까지 확정했지만 Latest-Only Processing을 결정하기 전의 계약 이력입니다. 현재 구현/운영 기준은 현재 Sync Contract · 개정 3입니다.

이 과거 개정이 확정했던 것

D1 Project Watermark
D2 5m Overlap + fixed upper
D3 NEW / CHANGED / UNCHANGED
D4 semantic_v2 · Source 변경 판별 프로필
D5 Loop별 Checkpoint / Resume
D6 Project Registry / Knowledge Retention
D7 SOURCE_COMMITTED ≠ PUBLISHED + Source Ready
D8 Loop-local Run status
D9 Two-Loop Operational Architecture

현재 개정 3에서 추가된 것

D10 Latest-Only Knowledge Processing. 같은 Jira Issue의 여러 Source 상태가 backlog에 쌓이면 Source History는 모두 보존하지만 아직 완료되지 않은 과거 Work는 최신 Work에 의해 superseded됩니다.

번호 읽는 법

여기서 개정 2는 Sync Contract 계열 번호입니다. State DB, Knowledge DB, Document Shell의 번호와 비교하지 않습니다.
