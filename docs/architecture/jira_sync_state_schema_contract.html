4. Loop A State

source_sync_run source_run_id = sr_ + UUID4 started_at / finished_at / upper_bound discovery_status / source_status / run_status project_state project_id / current key,name / visibility committed_watermark / last source success source_project_run (source_run_id, project_id) operation_kind / lower / upper candidate/new/changed/unchanged counts cursor_updated_at + cursor_jira_id source_status

5. Loop B State

processing_run processing_run_id = pr_ + UUID4 started_at / finished_at / run_status selected_count / published_count / failed_count backlog_before / backlog_after / error_summary

Source Run과 Processing Run은 1:1이 아닙니다.

6. Work Item · durable backlog

work_item_id = sw_ + deterministic SHA-256 identity material = jira_id + source_hash + source_hash_profile UNIQUE(jira_id, source_hash, source_hash_profile) Source observation lineage first_discovered_source_run_id last_observed_source_run_id last_source_committed_run_id last_source_committed_at last_observed_at Processing lineage last_processing_run_id knowledge_status embedding_status publish_status last_published_at

7. Source Ready Gate · 2-Loop 필수 불변식

Loop B claim 가능 조건 last_source_committed_run_id IS NOT NULL AND last_source_committed_run_id = last_observed_source_run_id

후보 Issue를 처리하는 T2에서 Work Item row를 먼저 durable하게 만들 수 있지만, Project 전체 Source Commit 전에는 Loop B가 소비할 수 없습니다.

T2 Candidate → actual Source files durable → Work Item UPSERT → last_observed_source_run_id = current → cursor/count commit T3 Project Source Commit · SAME State transaction → source_project_run.source_status = source_committed → project_state.committed_watermark = upper → 이번 Project/Run Work Item: last_source_committed_run_id = current last_source_committed_at = now → COMMIT 그 다음에만 Loop B eligible

8. Crash Safety

Loop A

실제 Source 파일이 먼저 durable. Candidate checkpoint가 나중. Source Commit + Watermark + Work Item Ready Gate는 같은 transaction.

Loop B

Knowledge/Embedding actual output 먼저, State completed 나중. Actual Retrieval switch 먼저, State published 나중.

11. Identity

Project = Jira project_id Issue = Jira jira_id Source Run = sr_ + UUID4 Processing Run = pr_ + UUID4 Work Item = sw_ + deterministic SHA-256 Source Project Run PK = (source_run_id, project_id)
