Sync State Schema Contract
FROZEN v1

Sync Contract D1~D8을 실제 운영 상태 저장소로 옮기기 위해 S1~S7에서 합의한 저장소, 테이블, 컬럼, 상태, Transaction, Migration, ID, DDL을 하나의 구현 기준으로 통합합니다.

FROZEN BASELINE · S1~S7 APPROVED · NO IMPLEMENTATION YET

1. 책임 경계

Control Plane · State DB

data/state/collector.db를 Operational Sync State DB로 확장합니다.

Run, Project 현재 상태, Watermark, Source cursor, Work Item, retry/error를 관리합니다.

Data Plane · Knowledge DB

Issue Version, Generation, Attempt, Knowledge Item, Evidence, Review 등 실제 업무지식과 족보를 보존합니다.

원칙: State DB는 “어디까지 진행됐는가”, Knowledge DB는 “무엇이 만들어졌는가”를 답합니다.

2. S1 · 저장소와 Migration

기존 data/state/collector.db 재사용 → 의미 없는 그대로 사용 X → explicit versioned migration 필수 → legacy table/data 보존 → Operational State 확장

Silent auto-migration은 금지합니다. 기존 DB는 fingerprint를 확인하고 consistent backup, validation, regression Gate를 통과한 뒤에만 v1로 전환합니다.

3. S2 · 4개 Operational Domain Table

sync_run

전체 Source Sync 범위와 집계 상태.

project_state

Project identity, visibility, Watermark 현재 상태.

sync_project_run

Run×Project Source 처리 이력과 Resume cursor.

sync_issue_change

NEW/CHANGED semantic Work Item의 downstream 진행 상태.

Migration 감사용 state_schema_migration은 별도 Technical Metadata입니다.

4. S3 · 필수 컬럼과 상태

sync_run → fixed upper → discovery_status / source_status / publish_status / run_status project_state → project_id / current key,name / visibility → committed_watermark / last source success sync_project_run → operation_kind / lower / upper → candidate,new,changed,unchanged counts → cursor_updated_at + cursor_jira_id → source_status sync_issue_change → jira_id + source_hash + semantic_v2 → discovered_run / last_attempt_run → Knowledge / Embedding / Publish checkpoint

UNCHANGED는 Work Item을 만들지 않고 Project 집계와 Source cursor만 남깁니다.

5. S4 · Transaction / Crash Safety

T0 Run Start → fixed upper durable T1 Discovery Commit → 완전한 snapshot만 Registry 반영 T2 Candidate → 실제 Source durable 후 count/work/cursor commit T3 Project Commit → source_committed + Watermark SAME transaction T4 Downstream → 실제 산출물 먼저, State completed 나중 T5 Publish → 실제 Retrieval 전환 먼저, State published 나중 T6 Run Finalize → completed / partial / failed 집계
최우선 불변식: Watermark는 Source Commit보다 앞서가지 않습니다.

6. S5 · Migration Contract

STATE_SCHEMA_VERSION = 1 PRAGMA user_version = 1 legacy user_version 0 → empty / known legacy / unknown fingerprint 구분 known legacy → explicit migration → SQLite consistent backup → additive new tables → legacy rows 보존 → integrity/schema/regression PASS → cutover
No Guess Backfill

Legacy project_runs에서 stable project_id나 committed Watermark를 추정하지 않습니다. 첫 Operational Source Sync부터 정식 상태를 만듭니다.

8. S7 · DDL / Constraint / Index

실제 CREATE TABLE / CHECK / FK / UNIQUE / INDEX의 구현 기준은 S7 Final 문서를 따릅니다.

DB가 직접 막음

enum 오류, 음수 count, cursor pair 불일치, stage 순서 모순, Work Item 중복.

StateStore가 막음

Source Commit + Watermark 원자성, Project upper와 Run upper 일치.

Validator가 막음

Knowledge logical ID 존재, 실제 Retrieval Publish, Source Head/Published Head 일치.
