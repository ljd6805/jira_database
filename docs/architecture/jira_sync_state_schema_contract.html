4. Work Item identity

work_item_id = sw_ + deterministic SHA-256 identity material = jira_id + source_hash + source_hash_profile UNIQUE(jira_id, source_hash, source_hash_profile)

중간 Source 상태를 supersede해도 Work Item identity나 Source History를 삭제하지 않습니다.

5. Work Lifecycle

work_status의미
pending최신 Source Ready Work, 아직 미처리
runningLoop B가 현재 처리 중
published실제 Retrieval Publish까지 완료
failed최신 Work였지만 처리 실패, 재시도 가능
superseded더 최신 Source 상태가 Source Commit되어 더 이상 AI 처리 가치가 없음
superseded_by_work_item_id superseded_at supersede_reason = newer_source_version

6. Source Ready + Latest Gate

Loop B claim 가능 last_source_committed_run_id IS NOT NULL AND last_source_committed_run_id = last_observed_source_run_id AND work_status IN ('pending','failed') AND superseded_by_work_item_id IS NULL

Source Commit 완료뿐 아니라 같은 Jira Issue 중 현재 최신 Work여야 합니다.

7. Project Source Commit에서 supersede도 함께 처리

새 상태 C Work Item이 Project SOURCE_COMMITTED SAME State DB transaction 1. source_project_run.source_status = source_committed 2. project_state.committed_watermark = upper 3. C last_source_committed_run_id = current 4. 같은 jira_id의 이전 미완료 Work work_status IN (pending, failed, running) → work_status = superseded → superseded_by_work_item_id = C → superseded_at = now 5. COMMIT

이미 Published된 과거 Work는 History로 남깁니다.

8. Processing 중 새 상태가 들어오면

상태 B Work running → 상태 C SOURCE_COMMITTED → B work_status = superseded → OpenCode B 응답 도착 → Worker 최신성 re-check → superseded 확인 → Active Knowledge 저장/Embedding/Publish 중단 → stale_inflight_detected log

9. Stage 상태와 work_status의 역할

work_status

knowledge / embedding / publish_status
