5. State DB ↔ Knowledge DB 연결

두 DB는 별도 SQLite이므로 서로 직접 FK를 걸 수 없습니다. 아래는 애플리케이션이 검증하는 Logical Reference입니다.

sync_issue_change.jira_idLogical Reference → issue.jira_id
sync_issue_change.issue_version_idLogical Reference → issue_version.issue_version_id
sync_issue_change.knowledge_generation_idLogical Reference → knowledge_generation.knowledge_generation_id
읽는 규칙
같은 DB 안의 실제 FK와 DB를 넘는 Logical Reference를 동일한 관계로 취급하지 않습니다. 이 구분이 전체 ERD 해석의 핵심입니다.

7. Issue 한 건이 흐르는 순서

ERD를 외우지 말고 데이터 한 건을 따라가면 구조가 훨씬 단순해집니다.

1. 변경 발견sync_issue_change
2. Source 저장issue + issue_version
3. Knowledge 생성knowledge_generation
4. Attemptknowledge_attempt
5. 문장/근거knowledge_item + knowledge_evidence
6. 품질 검토knowledge_review + review_finding
7. 검색 반영BGE-M3 → FAISS
8. 상태 반영State DB published
