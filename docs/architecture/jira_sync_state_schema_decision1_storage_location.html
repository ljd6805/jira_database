S1 · CURRENT · REVISED BOOTSTRAP INTERPRETATION

Operational State DB는
data_root/state/collector.db에 둔다.

State DB의 역할과 파일명은 유지하되, 기존 파일럿 DB를 반드시 재사용한다는 의미는 폐기합니다. 현재 공식 경로는 Fresh Bootstrap입니다.

현재 위치 규칙

Formal Real Test / Operation data_root = ./data → data/state/collector.db Smoke data_root = ./data_smoke → data_smoke/state/collector.db 둘 다 같은 Operational State Schema 개정 3 둘 다 Control Plane 역할

Control Plane / Data Plane

Control Plane · State DB source_sync_run project_state source_project_run sync_issue_change processing_run Data Plane · Knowledge DB Issue Version / Generation / Attempt / Item / Evidence / Review

Fresh Bootstrap이 기본

새 Smoke와 정식 Real Test에서는 빈 DB를 현재 Schema 개정 3으로 직접 초기화합니다. 기존 파일럿 collector.db를 이어받지 않습니다.

Migration은 조건부

기존 legacy collector.db를 꼭 재사용해야 하는 별도 환경에서만 explicit Migration이 필수입니다. 현재 공식 Real Test에는 해당하지 않습니다.

왜 State DB 역할은 하나로 유지하나?

Source cursor, Watermark, Work backlog, Processing checkpoint는 모두 Control Plane 상태입니다. Fresh DB를 만들더라도 이 책임 경계는 변하지 않습니다.

버전 번호 주의

STATE_SCHEMA_VERSION = 3은 Operational State DB의 개정 번호입니다. M7 Knowledge DB Schema 개정 1과는 별도입니다.
