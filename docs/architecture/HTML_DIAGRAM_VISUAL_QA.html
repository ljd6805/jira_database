1. 수정 전에는 무엇이 잘못됐나?

Connector 문제

모든 edge를 cubic Bézier로 만들었고 주변 node를 장애물로 고려하지 않았습니다. 정적 geometry check에서 62개 중 16개 connector가 다른 node 영역을 통과했습니다.

Label 문제

label을 곡선의 기하학적 중간점(t=0.5)에 기계적으로 놓았습니다. 32개 edge label이 node와 겹쳤습니다.

잘못된 접근

선 하나씩 좌표를 손으로 옮겨 “지금 화면만” 보기 좋게 보정합니다. Node 위치가 조금만 바뀌면 다시 깨집니다.

채택한 접근

router가 node bounding box를 장애물로 보고 안전한 corridor를 자동 탐색하며, label도 collision-free 후보 위치를 찾게 합니다.

5. 앞으로 적용할 6가지 규칙

단순 flow는 CSS Grid/Flex

2~5개 직선 단계에 굳이 SVG network를 쓰지 않습니다. 전용 arrow column/row가 가장 안전합니다.

복잡한 graph만 obstacle-aware router

Connector는 node bounding box + clearance 영역을 통과하지 않아야 합니다.

Label midpoint 고정 금지

기하학적 중간점이 아니라 node/label과 겹치지 않는 위치를 선택합니다.

교차선에는 halo

Dense graph에서 교차가 남을 수 있으므로 배경 halo로 선의 경계를 보이게 합니다.

Node focus 제공

Hover 시 직접 연결된 node/edge만 강조해 하나의 경로를 추적할 수 있게 합니다.

모바일에서 억지 축소 금지

복잡한 network는 최소 너비와 horizontal scroll을 허용합니다. 360px 안에 모든 걸 눌러 넣는 건 반응형이 아니라 미니어처입니다.

7. 초보자 체크

Q. 선끼리 한 번도 교차하면 안 되나?아니요. 복잡한 graph에서는 edge-edge 교차가 불가피할 수 있습니다. 중요한 것은 제3의 node 관통을 피하고, 교차 지점을 halo/focus로 구분 가능하게 만드는 것입니다.
Q. 예쁜 Bézier curve가 항상 나쁜가?아니요. 장애물 회피가 필요 없는 단순 diagram에서는 괜찮습니다. Dense 관계도에서 주변 node를 고려하지 않는 curve를 기계적으로 쓰는 것이 문제입니다.
