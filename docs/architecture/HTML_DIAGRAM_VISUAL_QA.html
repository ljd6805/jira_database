1. 감사 결론

문제는 “화살표 색”이 아니라 렌더링 알고리즘이었습니다.

Before

모든 edge를 cubic Bézier로 만들고, label을 곡선의 t=0.5 지점에 기계적으로 배치했습니다. 주변 노드를 보지 않으므로 조밀한 view에서는 충돌이 필연적이었습니다.

After

노드 바깥의 grid corridor를 탐색해 직교 경로를 선택하고, label은 node/다른 label과 겹치지 않는 후보 위치를 찾습니다. 필요한 경우 짧은 leader line으로 원래 edge와 연결합니다.

수정 전 정적 geometry check
62개 connector 중 16개가 다른 node 영역을 통과했고, 32개 edge label이 node와 겹쳤습니다. 특히 Entity Map과 SQLite Boundary view가 가장 조밀했습니다.
수정 후 정적 geometry check
4개 view의 62개 connector 모두 node 관통 0건, 62개 label 모두 node/label 상호 충돌 없이 배치되었습니다. 선과 선의 교차는 복잡한 관계도 특성상 일부 남을 수 있으므로 halo와 hover focus로 구분 가능하게 했습니다.

3. 재발 방지 규칙

1

단순 flow는 CSS Grid/Flex. 2~5개의 직선 흐름에 SVG network를 쓰지 않습니다. 화살표 전용 열/행을 두면 box 관통 문제가 원천적으로 사라집니다.

2

복잡한 관계도는 직교 routing. connector는 node bounding box + clearance 영역을 지나가지 않습니다. 곡선이 예뻐 보여도 장애물 회피가 없으면 사용하지 않습니다.

3

label은 midpoint 금지. edge의 기하학적 중간점이 아니라 node/기존 label과 겹치지 않는 위치를 선택합니다. 공간이 없으면 annotation lane으로 이동하고 leader line을 사용합니다.

4

교차선에는 halo. 선끼리 교차할 수밖에 없는 dense graph에서는 배경색 halo를 먼저 그린 뒤 실제 edge를 그려 교차점을 분리합니다.

5

node focus 제공. hover 시 직접 연결된 node/edge만 강조해 큰 관계도에서 한 경로를 추적할 수 있게 합니다.

6

모바일에서 억지 축소 금지. network SVG에는 최소 너비를 두고 horizontal scroll을 허용합니다. 모든 내용을 360px에 눌러 넣는 것은 “반응형”이 아니라 “미니어처”입니다.
