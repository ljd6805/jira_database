Documentation Policy

이 프로젝트의 문서는 결과 보고서가 아니라 사람과 Agent가 같은 상태를 복원하기 위한 프로젝트 상태 저장소입니다. 사람용 문서는 HTML로 통일하고, 버전 표기는 숫자보다 대상과 현재/과거 상태를 먼저 보여줍니다.

1. Hub는 HTML Only

강제 규칙
docs/index.html의 로컬 문서 링크는 모두 .html이어야 합니다. Hub에서 .md로 직접 이동하는 링크를 만들지 않습니다.

사람이 읽는 문서

Overview, Design, Policy, Status, Completion, Troubleshooting, Decision Log의 Hub 노출본은 HTML.

Markdown 허용

README/AGENTS/Skill 같은 운영 파일과 raw 실행 로그·CHANGELOG 등 기록용 소스는 유지 가능.

Log도 Hub에서는 HTML

원본 로그를 .md로 남기더라도 Hub에서 읽게 할 경우 HTML companion을 만들고 HTML에 연결.

1.5. DOCUMENT SHELL · 개정 1 · 고정 프레임

2026-08-27 고정 규칙
Hub는 assets/hub-frame.css의 문서 UI 프레임 개정 1 구조를 사용하고, 모든 일반 HTML 문서는 assets/document-shell.css + document-navigation.js를 사용합니다. 이 개정 번호는 DB/Sync Contract 버전과 무관합니다.
  • 모든 문서는 이전 문서 / 문서 Hub / 다음 문서 세 버튼을 항상 표시합니다.
  • 첫/마지막 문서도 버튼을 숨기지 않고 disabled 상태로 자리를 유지합니다.
  • Hub의 5개 기본 영역과 공통 스타일은 임의로 재구성하지 않습니다.
  • 새 HTML 문서는 템플릿을 복사하고 python tools/docs/sync_document_shell.py --write를 실행합니다.
  • 완료 전 --check와 문서 회귀 테스트를 통과해야 합니다.

1.6. 버전 숫자는 “대상 + 상태 + 개정”으로 씁니다

새 강제 규칙 · 2026-08-31
사람용 본문에서 v1, v2, v3만 단독으로 던지지 않습니다. 같은 숫자라도 서로 다른 대상의 독립된 번호 체계일 수 있으므로, 현재/과거 상태와 대상 이름을 먼저 적습니다.
피할 표현권장 표현
v3현재 운영 규칙 · Sync Contract · 개정 3
State Schema v2과거 Operational State 설계 · 개정 2 · 현재 구현 기준 아님
Knowledge DB v1실제 구현 완료 · Knowledge DB Schema · 개정 1
semantic_v2semantic_v2 · Source 변경 판별 hash profile
Document Shell v1문서 UI 프레임 · 개정 1 · DB와 무관
숫자 크기 비교 금지
Operational State Schema 개정 3과 Knowledge DB Schema 개정 1은 서로 다른 대상입니다. 3 > 1이라는 이유로 Knowledge DB가 낡았다고 판단하지 않습니다.

공식 설명은 버전 표기 가이드를 따릅니다. 공통 Document Shell은 버전 표현이 있는 HTML에 이 안내를 자동 표시합니다.

1.7. 시각화는 설명을 대체하지 않고 보강한다

새 강제 규칙 · 2026-08-31
시각화는 설명을 대체하지 않고 보강한다. 디자인/레이아웃/ERD/다이어그램 개선은 기존 설명을 없애는 작업이 아니라 이해를 돕는 시각 계층을 추가하는 작업입니다.
  • 리팩터링 전 존재하던 기존의 유효한 설명, 표, 예시, 주의사항, Decision 이유, Source of Truth 링크를 디자인 개선만을 이유로 임의 삭제하거나 과도하게 축약하지 않습니다.
  • 기본 읽기 순서는 가능하면 그림 → 상세 설명 → 관계/표 → 쉬운 예시 → Source of Truth 로 구성합니다.
  • 복잡해서 시인성이 떨어지면 설명을 지우는 대신 그림을 여러 장으로 분리하거나 카드/표와 역할을 나눕니다.
  • 내용 삭제/축약은 사용자가 명시적으로 삭제/축약을 요청했거나, 코드/DDL/검증 결과와 비교해 오래되어 틀린 내용임이 확인된 경우에만 허용합니다.
  • 틀린 내용을 제거하거나 대체할 때는 무엇을 왜 바꿨는지 삭제 이유를 문서에 남긴다. historical 의미가 있으면 삭제보다 superseded/historical 표시를 우선합니다.
  • 시각 리팩터링 완료 전 before/after를 비교하여 정당한 이유 없는 정보 손실이 0건인지 확인합니다.
금지 예
“레이아웃이 복잡하다”, “그림을 넣었다”, “더 깔끔해 보인다”는 기존 설명을 삭제하는 근거가 아닙니다. 그림은 요약/탐색용이고, 상세 설명은 이해/검증용으로 함께 유지합니다.

2. 왜 이렇게 관리하는가

이 프로젝트는 설계 구조, 데이터 관계, Gate와 실환경 검증 수치를 반복해서 되짚어야 합니다. Markdown은 원시 기록에는 편하지만, 사람용 학습/복기 문서의 가독성과 시각적 구조를 일정하게 유지하기 어렵습니다. 또한 버전 숫자를 대상 없이 쓰면 State DB, Knowledge DB, 문서 UI, 내부 hash profile이 서로 같은 버전 계열처럼 보일 수 있습니다. 따라서 형식과 언어 규칙을 함께 고정합니다.

3. 기존 Markdown 처리 원칙

한 번에 전부 삭제하지 않습니다.
기존 테스트, Agent 지침, 과거 링크가 특정 MD 경로를 참조할 수 있으므로 legacy Markdown은 내부 호환/기록 목적으로 일시 보존할 수 있습니다. 다만 Documentation Hub에서는 연결하지 않습니다.
사람용 진입점
  docs/index.html
      ↓
  *.html only

내부/기록 계층
  README.md / AGENTS.md
  *_LOG.md / CHANGELOG.md
  legacy contract *.md (migration 중에만 임시 보존 가능)

새로 만드는 사람용 문서는 HTML-first로 작성합니다. legacy non-log MD를 장기간 유지할 이유가 사라지면 별도 migration 작업에서 참조·테스트를 정리한 뒤 제거합니다.

README.md                              # repository entrypoint

현재 Milestone의 상세 사람용 설계 문서는 해당 docs/status/M<N>_*.html 또는 명시된 HTML contract를 사용합니다.

5. Milestone HTML 보존 규칙

  1. Milestone이 CURRENT가 되는 시점부터 docs/status/M<N>_*.html을 둡니다.
  2. DONE 이후에도 HTML을 삭제하지 않습니다.
  3. 코드/Schema/Gate/검증 결과가 바뀌면 관련 HTML도 같은 작업 단위에서 갱신합니다.
  4. 핵심 본문은 HTML 파일 자체에 정적으로 포함합니다.
  5. 외부 CDN이나 원격 payload가 없어도 핵심 내용을 읽을 수 있어야 합니다.
  6. fetch() + DecompressionStream 방식의 압축 fragment loader를 Milestone 문서에 사용하지 않습니다.
  7. HTML이 실제 코드/검증보다 더 강한 사실을 새로 만들지 않습니다.

6. 삭제 / 이동 승인 규칙

사용자 승인 없이 Milestone HTML 삭제 금지
docs/status/M*.html의 삭제, 이름 변경, 다른 형식으로 대체, archive 이동은 일반 정리 작업으로 보지 않습니다. 삭제하기 전에 이유와 영향 범위를 사용자에게 설명하고 명시적 승인을 받아야 합니다.

승인이 없으면 삭제 대신 보존 + superseded/historical 표기를 우선합니다. Agent는 이 규칙이나 관련 회귀 테스트를 사용자 승인 없이 약화해서는 안 됩니다.

7. 변경 단위 규칙

방향을 바꾸는 결정, 데이터 계약 변경, Milestone 상태 변경은 코드만 바꾸고 끝내지 않습니다.

DESIGN
→ 계약 합의 / 문서화

IMPLEMENTATION
→ 코드 / DDL / Tool 구현

VALIDATION
→ unit / integration / real-data 검증

DOCUMENTATION SYNC
→ Current Source와 실제 상태 일치
→ Hub local links = HTML only
→ 버전 언어 = 대상 + 상태 + 개정
→ 시각화 추가 시 기존 설명 coverage 보존
→ 관련 HTML 갱신

8. 자동 회귀 방지

기본 테스트
tests/test_documentation_hub_html_only.py가 Hub의 로컬 anchor가 모두 .html인지, 실제 파일이 존재하는지 검사합니다.
pytest tests/test_documentation_hub_html_only.py
pytest tests/test_documentation_current_state.py
pytest tests/test_document_shell_consistency.py
pytest tests/test_documentation_content_preservation_rule.py

Hub에 .md 링크가 다시 추가되거나 존재하지 않는 HTML을 연결하면 문서 Gate가 실패해야 합니다. 시각화 개선 규칙이 Agent/Policy/Skill 중 한 곳에서 사라져도 회귀 테스트가 실패해야 합니다.

9. 작업 종료 체크

  • Current Milestone과 Next Action이 실제 상태와 같은가?
  • Entity/Cardinality/ID 계층이 현재 코드와 같은가?
  • Decision 이유가 HTML 또는 raw log에 보존되는가?
  • M0부터 현재 Milestone까지 HTML이 존재하는가?
  • Documentation Hub의 로컬 링크가 전부 .html인가?
  • 새 사람용 문서를 MD로만 추가하지 않았는가?
  • 버전 숫자가 대상/상태 없이 단독으로 보이지 않는가?
  • Historical/Baseline 문서가 현재 구현 기준처럼 보이지 않는가?
  • semantic_v2 같은 내부 이름을 문서 버전처럼 설명하지 않았는가?
  • 시각화/레이아웃 개선 전후에 기존 설명·표·예시·주의사항 coverage가 유지되는가?
  • 설명을 삭제/축약했다면 사용자 요청 또는 틀린 내용이라는 근거와 삭제 이유가 기록되어 있는가?
  • HTML 삭제/이동이 있다면 사전 사용자 승인을 받았는가?
