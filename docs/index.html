3. S5에서 지키려는 핵심

명시적 Migration

기존 legacy DB는 평범한 startup에서 몰래 변경하지 않습니다.

Fail Closed

user_version=0이어도 기대 legacy fingerprint와 다르면 자동 Migration을 거부합니다.

Backup First

SQLite consistent backup과 무결성 검증을 통과한 뒤에만 원본 DB를 변경합니다.

Additive Migration

기존 4개 legacy table/data는 삭제·rename하지 않고 새 운영 테이블을 추가합니다.

No Guess Backfill

과거 project_runs에서 stable project_id나 committed Watermark를 추정하지 않습니다.

Validation Gate

Schema/integrity/legacy regression/migration tests가 모두 PASS해야 운영 Sync를 시작합니다.
