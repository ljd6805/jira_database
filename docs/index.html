3. 운영 서비스 핵심

Loop A · Source Sync

Jira Download, RAW/ANALYSIS, semantic_v2 변경 판별 프로필, Source Commit, Watermark, 모든 Source 상태 보존.

Loop B · Latest-Only Processing

Source-ready이면서 최신인 Work만 OpenCode, Knowledge, BGE-M3, FAISS, Atomic Publish합니다.

Supersede

더 최신 Source 상태가 Commit되면 이전 pending/failed/running Work는 삭제하지 않고 superseded 상태로 남깁니다.

Structured Logging

work_item_superseded, stale_inflight_detected 등을 Jira 본문 없이 기록합니다.

Last-known-good MCP

Central MCP는 두 Loop와 독립적으로 마지막 안전 Published Corpus를 제공합니다.

Observability

Source Lag / Publish Lag / Latest Backlog / supersede ratio / OpenCode latency를 분리 측정합니다.
