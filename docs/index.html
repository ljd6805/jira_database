1. 데이터가 어떻게 변해가는가

이 프로젝트는 같은 Jira 데이터를 계속 덮어쓰는 구조가 아니라, 역할이 다른 계층을 차례로 추가합니다.

RAWJira API에서 읽은 사실 snapshot. 재처리의 기준.
ANALYSISRAW를 프로그램이 다루기 쉽게 결정적으로 정규화한 사실.
KNOWLEDGE INPUTIssue 한 건의 관련 사실을 한 Package에 모은 마지막 deterministic 입력.
KNOWLEDGE / REVIEW검색 가치가 높은 의미 압축 + Evidence + 품질 검토 이력.
SQLiteVersion/Generation/Attempt/Item/Evidence/Review와 History를 관계형으로 materialize.
Embedding · CURRENTActive accepted Knowledge Item을 BGE-M3 1024차원 vector로 변환.
FAISS · M9질문과 의미가 가까운 active Knowledge를 빠르게 찾는 vector index.
MCP · M10Agent가 검색 근거와 출처를 표준 도구로 호출하는 기능형 MVP.

3. 자주 나오는 용어

RAG질문에 답하기 전에 관련 근거를 검색해 LLM에게 함께 제공하는 방식. “오픈북 시험”에 가깝습니다.
Embedding문장의 의미를 숫자 vector로 바꾸는 것. 현재 모델은 BAAI/bge-m3, dense dimension 1024입니다.
FAISSvector끼리 가까운 후보를 빠르게 찾는 검색 index. 원문 DB가 아닙니다.
MCPAgent가 search/get 같은 기능을 표준 방식으로 호출하기 위한 도구 연결 규격입니다.
Generation같은 Issue Version + Knowledge Contract를 지식화하는 retry lineage.
AttemptGeneration 안에서 실제로 실행된 1차/2차/3차 생성 시도. ka_ ID와 attempt_no를 가집니다.
EvidenceKnowledge가 주장하는 내용의 실제 근거 위치. 최종적으로 source까지 round-trip 가능해야 합니다.
ActiveHistory 중 현재 기본 검색에 사용하도록 승인된 Knowledge Generation 상태입니다.
