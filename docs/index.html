3. FROZEN Contract 핵심

놓치지 않기

Project별 Watermark + 5분 Overlap + 고정 upper.

변경분만 처리

Jira updated는 후보 탐색, jira_id + semantic_v2 source_hash로 실제 변경 판정.

실패 지점부터 재개

Source/downstream Checkpoint를 분리하고 completed 결과는 재사용.

지식 보존

Project/Issue 삭제·비노출은 Knowledge 삭제 이벤트가 아니며 Retrieval을 계속 제공합니다.

안전한 Publish

Source Commit과 Publish를 분리하고 새 Publish가 완성될 때까지 기존 Published Knowledge 유지.

정확한 Run 상태

completed / partial / failed는 이번 Sync의 durable progress 기준이며 기존 Knowledge 서비스 상태와 분리.
