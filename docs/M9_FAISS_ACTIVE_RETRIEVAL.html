FAISS + Active Retrieval
상세 계약

M8의 검증된 285개 BGE-M3 embedding을 exact retrieval index로 만들고, 질문을 같은 vector space에서 Top-3 후보로 찾는 M9 계약입니다. M9-01 설계는 확정됐고 M9-02 구현/CI는 PASS, M9-03 실데이터 검증이 다음입니다.

1. M9 책임

질문 text → BGE-M3 query vector 1024-d → L2 normalize → FAISS IndexFlatIP exact cosine → Top-3 → faiss_position → embedding_id(emb_) → knowledge_item_id(ki_) M10 → ki_ → Knowledge / Evidence resolve → MCP
M9 경계 Evidence Builder와 MCP는 구현하지 않습니다. 후보 identity + score까지가 M9 책임입니다.

3. Identity

rc_

Retrieval Contract. index type, metric, normalization, query profile, Top-k 정책, model/profile/dimension을 식별합니다.

fi_

FAISS Index Artifact. source embedding snapshot SHA-256과 build profile을 식별합니다.

position

FAISS 내부 locator일 뿐 stable identity가 아닙니다. 반드시 emb_와 ki_로 역참조합니다.

4. Artifact

index.faiss index.mapping.jsonl index.manifest.json mapping: faiss_position embedding_id knowledge_item_id knowledge_attempt_id knowledge_generation_id issue_version_id category ordinal embedding_text_hash

Manifest에는 rc_/fi_, source embedding SHA, mapping/index SHA, FAISS version, count/dimension, query 정책을 기록합니다.

완료 marker = manifest 파일 일부만 바뀐 상태는 SHA가 맞지 않아 검색기가 거부합니다.

7. 확장 시 ANN

Flat은 영구 고정이 아니라 exact test oracle입니다. 데이터가 커져 p95 latency, RAM, QPS, rebuild 시간이 목표를 넘으면 IndexHNSWFlat 또는 IndexIVFFlat을 benchmark합니다.

Flat Top-k = exact reference ANN Top-k = candidate → recall@k + p95 latency + memory + throughput 비교 → 필요할 때만 전환

ANN으로 바뀌어도 position → emb_ → ki_ → Evidence 계약은 유지합니다.
