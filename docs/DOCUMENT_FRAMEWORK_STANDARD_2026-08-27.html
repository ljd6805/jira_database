DOCUMENT FRAMEWORK v1 · DECIDED · 2026-08-27

문서의 내용은 늘어나도
문서의 틀은 흔들리지 않게

Documentation Hub와 모든 HTML 문서의 공통 탐색 규칙을 하나의 프레임으로 고정합니다. 앞으로 새 문서를 만들 때마다 내비게이션을 다시 발명하지 않습니다.

1. 이번에 고정한 것

Hub Frame v1

Hub는 5개 기본 영역과 공통 카드/색상/폭을 assets/hub-frame.css에서 관리합니다.

Document Shell v1

모든 일반 HTML 문서는 같은 CSS/JS shell을 포함합니다.

Navigation Contract

이전 문서 / 문서 Hub / 다음 문서가 항상 같은 위치와 모양으로 존재합니다.

2. 내비게이션 계약

버튼은 없어지지 않습니다.
첫 번째 문서라 이전 문서가 없거나 마지막 문서라 다음 문서가 없더라도 버튼 영역 자체는 유지하고 disabled 상태로 표시합니다.
버튼항상 존재?동작
← 이전 문서예Registry 기준 이전 문서. 없으면 disabled.
⌂ 문서 Hub예항상 docs/index.html로 복귀.
다음 문서 →예Registry 기준 다음 문서. 없으면 disabled.

긴 문서에서도 탐색이 끊기지 않도록 같은 세 버튼을 문서 상단과 하단에 모두 제공합니다.

3. Hub의 고정 골격

1. 지금 어디부터 읽나?           # hub-start
2. 전체를 한 줄씩만 보면        # hub-roadmap
3. 운영 서비스 핵심              # hub-service
4. Milestone Visual Documents     # hub-milestones
5. Architecture / Policy          # hub-reference

새 문서가 추가되면 알맞은 영역에 카드/링크를 추가합니다. 기본 5개 영역 자체를 매번 재배치하거나 새 스타일을 임의로 만들지 않습니다.

파일책임

5. 새 문서를 만드는 방법

1. docs/templates/STANDARD_DOCUMENT_TEMPLATE.html 복사
2. 제목 / 본문 / 목적에 맞는 시각 요소 작성
3. docs/index.html의 알맞은 영역에 HTML 링크 추가
4. python tools/docs/sync_document_shell.py --write
5. python tools/docs/sync_document_shell.py --check
6. pytest tests/test_document_shell_consistency.py
7. 관련 문서 Gate까지 통과 후 commit

핵심은 4번입니다. 새 문서를 추가해도 공통 shell과 Registry를 사람이 일일이 맞추지 않고 동기화 도구가 정리합니다.

6. 기존 문서 처리

2026-08-27 migration에서 docs/index.html을 제외한 기존 HTML 전체를 Document Shell v1 대상으로 삼습니다. 문서별 본문/다이어그램은 유지하고, 공통 탐색 계층만 표준화합니다. 과거 문서의 내용까지 같은 디자인으로 강제로 갈아엎지는 않습니다. 내용 표현은 목적에 따라 달라도 밖을 감싸는 프레임과 이동 규칙은 동일합니다.

7. 변경이 필요할 때

Frame v1을 바꾸는 것은 일반 문서 편집이 아닙니다.
Hub 기본 영역, 버튼 계약, Registry 방식, 공통 asset 경로를 바꾸려면 DOCUMENTATION_POLICY.html과 이 문서를 함께 갱신하고 회귀 테스트도 같이 수정합니다.
